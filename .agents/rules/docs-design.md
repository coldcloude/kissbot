# 项目设计文档规范

- 系统设计文档（`system-design.md`）应包含：
  1. **组件体系** （必填）列出所有组件，说明各自的作用
  2. **组件间通信** （必填）表格列出哪些组件间需要通信，通信的时机是什么，交互哪些信息
  3. **关键设计** （可选）如果有关键的设计约定，放在这节
  4. 可以包含不在上述内容中，也不在禁止内容中的其他章节，如概述
  5. 一些独立的整体设计以`system-design-*.md`的形式作为补充，格式自由

- 组件设计文档（`components-design/` 下每个组件一个 MD 文件）应包含：
  1. **核心功能** （必填）将本组件的所有功能，梳理为不超过5个Epic，每个Epic包含：
    - **目标**：简要描述这个Epic完成了什么样的功能
    - **依赖**：需要哪些其他组件，具备哪些功能
    - **用户故事**：按照用户故事描述每个环节的功能，必须按照“作为一个<用户角色>，我要<执行动作>，以<达成目标>”的格式写，其中：
      - 用户角色：如管理员、一般用户等。也可以是用户，或者外部系统。不可以是本组件
      - 执行动作：用户的动作，如启动程序、打开界面、进行输入、配置定时器等。外部系统的动作，如发送消息、订阅消息、配置定时等
      - 达成目标：如显示某个列表，触发系统执行某个动作等
  2. **模块划分** （必填）组件内部都有哪些模块，一句话描述其用途
  3. **功能流程** （必填）每个核心功能是通过哪些模块如何完成的
  4. **关键设计** （可选）如果有关键的设计约定，放在这节
  5. 可以包含不在上述内容中，也不在禁止内容中的其他章节，如概述

- 禁止包含实现技术细节——缓存、懒加载等实现机制写到 docs/spec 目录

- 应保留设计层面的行为描述——组件在什么情况下做什么事、数据由哪些部分构成等，属于设计文档内容
