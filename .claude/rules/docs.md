# 项目设计文档规范

- 系统设计文档（`system-design.md`）必须包含：
  1. **组件体系** 列出所有组件，说明各自的作用
  2. **运行流程** 列出所有运行流程，说明每个环节由什么组件完成什么动作，整条流程的目的是完成一件什么事
  3. **组件间通信** 表格列出哪些组件间需要通信，通信的时机是什么，交互哪些信息

- 组件设计文档（`components-design/` 下每个组件一个 MD 文件）必须包含：
  1. **核心功能** 本组件最核心的功能，挑 1～3 个写
  2. **模块划分** 组件内部都有哪些模块，一句话描述其用途
  3. **功能流程** 每个核心功能是通过哪些模块如何完成的
  4. **关键设计**（可选）如果有关键的设计约定，放在这节

- 禁止包含哲学讨论——设计哲学归入 blog 目录

- 禁止包含实现技术细节——API 路径、参数格式、JSON 结构、文件格式、具体库名、缓存/锁等实现手段归入 docs/spec 目录

- 应保留设计层面的行为描述——组件在什么情况下做什么事、数据由哪些部分构成等属于设计文档内容
