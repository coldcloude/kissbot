````markdown
### 五、消息流程

**消息上行（管理员发消息 → agent）：**
```
1. 管理员在 Web UI 上选择会话（单聊或群聊），输入消息
2. Web UI → HTTPS POST /api/message/send { group_id, content, attachments? }
3. WebMessenger 收到 → 保存附件 → 构建 IncomingMessage
4. WebMessenger 通过 Messenger 注册的回调通知 ChannelManager
5. ChannelManager 消息入队
6. ChannelManager 处理队列：
   ├─ 推送记忆存储模块（memory-store）
   └─ 通过 WSS 发送给 nexus（目标 agent）
7. Nexus 接收 → Agentic Loop → 生成回复
```

**消息下行（agent 回复 → 管理员）：**
```
1. Nexus 生成回复 → 通过 WSS 发送给 ChannelManager
2. ChannelManager 按 channel_id 查找 WebChannel 实例
3. 消息入队 → 处理队列：
   ├─ 推送记忆存储模块
   └─ 调用 channel.send_message() → WebChannel
4. WebChannel 通过 WS 实时推送给 Web UI
5. 管理员看到回复
```

**群组管理流程：**
```
管理员在 Web UI 操作：
- 新建群组 → POST /api/groups/create → WebMessenger 更新内存 group 列表
  → 触发 GroupChangeHandler 回调 → ChannelManager 通知 nexus
- 编辑/删除群组同样触发通知
```
````

````markdown
**SSE 规范本身**（EventSource API）默认只支持 GET，不支持自定义 header：
```js
new EventSource('/api/events')              // ✅ 标准用法，只能 GET，不能加 header
new EventSource('/api/events', { withCredentials: true }) // ❌ 依然不能加自定义 header
```

**所以在浏览器环境下用 EventSource 只能用 GET，且只能传自定义 header，API key 只能放 URL 参数。**

**如果需要传自定义 header**（比如你要求的 `X-Api-Key`），就必须放弃 EventSource API，改用 `fetch POST` + `ReadableStream` 手动解析 SSE 格式：

const reader = response.body.getReader()
// 从 reader 读取并解析 SSE 事件流
```
````
