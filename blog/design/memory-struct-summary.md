# 记忆摘要设计

## 记忆摘要流程

- 每个 agent role 形成一个 case 森林
- Role 模式对应一个根，每个 Event 对应一个根
- case 树每个节点包括 case_name、摘要，如果为叶子 case 则包含原始记录列表，否则为复合 case，包含子 case列表
- Event case 树的根节点可以为叶子节点，Role case 树根节点固定为复合 case，并且固定摘要为空

- 将记忆加入 case 树时，每次只处理一个 Channel（messenger + user + group）的数据，分为两个步骤：
  - 定位
    1. 将等待摘要的记忆（新记忆）发送至 LLM 进行分组，并且判断是否属于 Channel 的当前 case
    2. 属于当前 case 的分组直接返回；不属于的按照分组中首条记忆的时间顺序，按组依次处理，从根节点开始遍历
    3. 遍历节点时，将新记忆和该节点所有子节点的名称、摘要一起发送至 LLM 判断属于哪个子节点
    4. 如果判断记忆不属于任何一个子节点，则新建一个叶子 case，作为当前遍历节点的子节点
    5. 定位到的子节点是叶子结点，则返回子节点 case，否则将该子节点作为新的遍历节点，继续遍历
    6. 当前 agent 为 Event 模式时，直接定位到 Event case 树的根节点，不存在则新建。Event case 树根节点如果是叶子节点，则直接返回，否则将该根节点作为遍历节点开始遍历
  - 归档
    1. 已定位的消息加入记忆时，meta 字段携带 case_name
    2. 将所有当前 Channel 的未处理的消息按 meta 中的 case_name 分组，每组单独处理
    3. 如果该 case 不是叶子，则直接跳过
    4. 每组新消息和所属 case 原摘要一起发送给 LLM 生成新摘要
    5. 将新消息追加到 case 中，并更新摘要
    6. 全部叶子 case 更新完成后，按受影响分支自底向上重算：当复合 case 的子节点更新过、且该节点不是 Role case 树根节点时，将该节点的原摘要和所有子 case 的摘要一起发送给 LLM 生成新摘要

- 每次定位前要先做归档
