# 记忆摘要设计

## 记忆摘要流程

- 每个 agent role 形成一个 case 树
- case 树每个节点包括 case_name、摘要，如果为叶子 case 则包含原始记录列表，否则为复合 case，包含子 case列表
- case 树的根节点固定为复合 case，并且固定摘要为空

- 将记忆加入 case 树时，每次只处理一个 Channel（messenger + user + group）的数据，方法如下：
    1. 将等待摘要的记忆（新记忆）发送至 LLM 进行分组，并且判断是否属于 Channel 的当前 case
    2. 属于当前 case 的记忆直接加入，不属于的按照分组中首条记忆的时间顺序依次处理，从根节点开始遍历
    3. 遍历节点时，将新记忆和该节点所有子节点的名称、摘要一起发送至 LLM 判断属于哪个子节点，并输出所属子节点的新摘要
    4. 如果判断记忆不属于任何一个子节点，则新建一个叶子 case，作为当前遍历节点的子节点
    4. 更新子节点的摘要，如果定位到的子节点是叶子结点，则插入记忆原始记录，否则将其作为新的遍历节点，继续遍历
    5. 当前 agent 为 Event 模式时，直接在根节点下查找或新建 Event 对应的节点，如果是叶子节点则直接插入，否则将该节点作为根节点开始遍历
