# Channel Web

## 目标

- 同时实现 Web 通信工具及 Channel Messenger 适配层
- 支持管理员和多个 agent 的单聊、群聊

## 设计

- 只有一个管理员，user_id 固定为 admin，其他用户均称为 user，user_id 为 u<数字>
- 每个 user 自动生成和管理员的单聊，group_id 为 a_<user_id>
- 除了管理员单聊群组外，可以新建群组，允许0人、1人、2人、或更多人数的群组
- Web 页面为管理员的界面，通过 SSE 接收 Channel Web 推送的消息，使用单独的管理员 API key
- user 均通过 WS 实现 Channel 接口接入
- Web 页面上管理员可以看到所有群组的消息，即使管理员不在群组中
- 管理员也不可向不包含自己的群组发送消息
- 附件保存到 Channel Web 本地，图片上传时自动生成缩略图，SSE 推送时显示缩略图，点击缩略图显示原图

- 一套前端界面可以在多个后端间切换
  - 首页显示已知后端列表，可以直接选择进入，也可以自定义输入
  - 后端列表放在站点根目录下的独立配置文件里、**不打进 JS bundle**，部署时直接覆盖构建产物

- 支持对话翻阅
  - 群组默认加载最近若干条记录，向上滚动后加载更多更早的记录
  - 可以根据时间定位到某条消息，并加载前后若干条记录，上下滚动加载更多记录

- UI 布局
  - 会话列表按最新消息降序
  - 未会话列表中，读数右对齐，超过 99 显示省略
  - 未加入群组时，展示消息，但输入框禁用
  - 消息区按内容类型分别渲染（文本/图片缩略图可点开原图/非图片文件显示下载链接/复合消息同气泡内分项/系统消息居中），admin 靠右用户靠左、滚动到顶部按锚点加载更早消息
  - 顶部下拉菜单切换群组管理与用户管理面板

## 实现细节

- 消息在 Messenger 本地落盘才算发送成功，消息时间以落盘时间重写，若落盘时间相对触发时间跨天，则落盘为触发当天的23:59:59
- 发送成功（落盘）后，才会触发推送 SSE（admin）和 WS（user）

- 附件存储
  - 附件分为本体、元数据文件、缩略图三个文件存储
  - 元数据读取走 LRU 缓存
  - 上传期间写临时文件，收满全部数据才转正（未完成的上传不产生正式文件）
  - 缩略图固定 200×200，非图片请求缩略图返回错误
  - 下载按固定块大小（64KB）推送
