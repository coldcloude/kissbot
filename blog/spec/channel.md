# 通道实现

## 实现细节

- 核心的交互逻辑提取为可复用的组件，包括服务端、客户端
  - 服务端对接消息工具，作为消息工具的代理，和客户端通信
  - 客户端对接消息工具的用户，作为 agent 或人的代理，和服务端通信
  - 消息工具抽象为 Messenger trait，客户端抽象为 Terminal trait

- 按照消息流动顺序调用
  - 发消息、上传文件、发送下载请求时，用户 -> 客户端 -> 服务端 -> 消息工具
  - 接收消息、下载文件时，消息工具 -> 服务端 -> 客户端 -> 用户

- 附件
  - 附件上传：
    1. 客户端发送消息中带有附件，服务器端返回key和transferId
    2. 客户端使用transferId发送附件payload
  - 附件下载：
    1. 客户端发送要下载的key，服务器端返回transferId
    2. 服务端使用transferId发送附件payload

- 消息存储
  - 当通道实现仅作为对接层时，不存储历史消息，所有历史消息由实际的消息工具保存
  - 当通道实现为包含消息工具的完整实现时，应有消息和附件存储、读取功能
