# kissbot-agent-nexus 模块设计

## 概述
Nexus — Agent 组件的 LLM 通信枢纽模块。智能体的"思考"部分，负责将外部输入和记忆加工为 LLM 可用的上下文，通过agentic loop调用 LLM 执行操作、生成回复。若 LLM 输出包含 tool call，则将 tool call 分派到同 Agent 内的 Station 模块执行。

Nexus 是 Agent 组件的一部分，与消息通道建立实时连接进行消息收发，与 memory-store、memory-ego 和 station 通过请求-响应方式通信。Agent 启动时可选择是否启用 nexus 模块。一个系统内可运行多个 agent 实例，每个实例可独立选择是否启用 nexus。

## 核心功能

### Epic 1：外部输入处理
- **目标**：接收来自外部消息、定时器和 API 三种入口的输入，区分并路由管理命令和普通消息到对应处理流程
- **依赖**：Epic 5（消息通道通信）
- **用户故事**：
  - 作为一个 nexus，我在从消息通道收到消息时，要检查消息来源和所属群组是否在已绑定的群组列表中，以丢弃非绑定群组的消息
  - 作为一个 nexus，我在从消息通道收到带有自回显标记的消息时，要与本地发送记录对比，以确认并丢弃自己发出的回显
  - 作为一个 nexus，我在收到任何入口的输入时，要检查是否以特定前缀开头，以识别管理命令并检查发送者是否在管理权限用户列表中，对管理员执行命令、对非管理员回复无权限
  - 作为一个 nexus，我在收到普通输入时，要进入agentic loop，以生成 LLM 回复

### Epic 2：LLM 交互
- **目标**：封装 LLM API 调用，支持多种 LLM 提供商和模型，构建完整的 LLM 上下文并调用
- **依赖**：Epic 3（上下文管理）、memory-ego（自我认知信息）
- **用户故事**：
  - 作为一个 nexus，我要在收到用户消息后构建包含系统消息和对话历史的完整上下文，以传入 LLM API 调用
  - 作为一个管理员，我要配置 LLM 调用的地址、密钥、模型和参数，以控制 LLM 的行为
  - 作为一个 nexus，我要在 LLM 调用失败时按可配置的策略重试，以提高请求成功率
  - 作为一个管理员，我要切换使用的 LLM 提供商，以使用不同的 AI 模型
  - 作为一个 nexus，我要在 LLM 返回回复后将思考过程记录到记忆系统，并将回复内容发送到消息通道

### Epic 3：上下文管理
- **目标**：管理内存中的 LLM 上下文，支持构建、增量追加和超长自动重置
- **依赖**：Epic 4（记忆读写）、memory-ego（自我认知信息）
- **用户故事**：
  - 作为一个 nexus，我要在启动或上下文重置时从 memory-store 读取最近历史记录并结合 memory-ego 的自我认知信息，以构建初始 LLM 上下文
  - 作为一个 nexus，我要在运行时每次收到用户消息和 LLM 回复后增量追加到上下文，以保持对话连续性
  - 作为一个 nexus，我要保存已发送消息的内容列表以识别和丢弃自己发出的回显消息，以避免形成对话循环
  - 作为一个 nexus，我要在上下文消息数量超过上限时自动触发重置，以防止 LLM token 占用无限增长

### Epic 4：记忆读写
- **目标**：在启动、模式切换、上下文重置时从 memory-store 和 memory-struct 读取历史记忆；在agentic loop中将思考、tool call、tool result 写入记忆系统；支持按模式（角色/事件）隔离记忆范围
- **依赖**：memory-store（记忆读写）、memory-struct（记忆索引查询）、memory-ego（自我认知信息）
- **用户故事**：
  - 作为一个 nexus，我要在启动或上下文重置时按当前模式从 memory-store 读取最近历史记录，以快速恢复近期对话脉络
  - 作为一个 nexus，我要在需要深入回顾时按当前模式查询 memory-struct 获取索引后的记忆，以获取完整的历史信息
  - 作为一个 nexus，我要在事件模式下只读取本事件范围内的记忆，以隔离不同事件的对话上下文
  - 作为一个 nexus，我要在agentic loop中将思考内容、工具调用指令、工具结果写入 memory-store，以使每条推理记录都被持久化
  - 作为一个 nexus，我要在写入失败时仅记录日志不重试，以避免阻塞后续操作
  - 作为一个 nexus，我要通过管理命令查询所有事件列表，以了解已记录的事件概况

### Epic 5：消息通道通信
- **目标**：作为客户端连接消息通道的服务端，支持多通道同时连接、心跳检测和断线重连
- **依赖**：kissbot-channel（消息通道服务端和绑定协议）
- **用户故事**：
  - 作为一个 nexus，我要在启动时读取配置中的通道绑定列表并为每个通道建立连接，以实现与多个消息通道的通信
  - 作为一个 nexus，我要在连接建立后自动获取通道信息并发送绑定请求绑定指定的用户，以接收该用户的消息
  - 作为一个 nexus，我要每个连接独立运行并支持心跳检测和断线自动重连，以保持通信的稳定性
  - 作为一个 nexus，我要从连接接收上行消息送入协调器处理，并根据目标 messenger ID 选择对应连接发送下行消息

### Epic 6：工具调用分派
- **目标**：解析 LLM 返回中的 tool call，区分内置工具和外置工具，分派到对应 Station 执行
- **依赖**：Epic 2（LLM 交互）、Station 组件
- **用户故事**：
  - 作为一个 nexus，我要在 LLM 返回包含 tool call 时解析工具名称和参数，以获取工具调用的详细信息
  - 作为一个 nexus，我要区分内置工具（如记忆查询）和外置工具，以便内置工具由自身执行而不发送 station
  - 作为一个 nexus，我要查找目标 station 地址并发送请求执行外置工具，以完成工具调用
  - 作为一个 nexus，我要在工具结果再次触发 LLM tool call 时支持多轮嵌套处理，以完成复杂的工具链调用

## 内部模块

### 1. 协调器
- 核心调度层，统一管理 nexus 所有入口（外部消息、定时器、API）
- 管理 nexus 生命周期（启动、模式切换、上下文重置）
- 将外部输入路由到管理命令处理或agentic loop
- 在启动时和上下文重置时从 memory-ego 加载自我认知信息设置为系统消息

### 2. 配置管理器
- 从配置文件加载所有配置
- 管理 LLM API 配置、通道绑定列表、管理权限用户列表、当前角色、当前模式、station 地址列表、memory 组件地址
- 支持运行时通过管理命令修改配置，修改后自动保存并通知监听器

### 3. LLM 客户端
- 封装 LLM API 调用（支持多种 LLM 提供商）
- 维护 LLM API 配置（地址、密钥、模型、参数等）
- 支持请求重试和超时控制
- 支持运行时热更新配置

### 4. 上下文构建器
- 管理内存中的 LLM 上下文消息列表
- 在启动/切换时接收记忆读取器读取的历史记录构建初始上下文，自动包含系统消息
- 运行时增量追加用户消息和助手回复
- 保存已发送消息内容列表，用于自回显消息的识别丢弃
- 上下文消息数量超上限时触发自动重置

### 5. 记忆读取器
- 在启动、模式切换、角色切换、上下文重置时调用
- 从 memory-store 读取最近若干条历史记录
- 角色模式下读取该角色所有记录，事件模式下只读本事件记录
- 支持查询事件列表

### 6. 记忆写入器
- agentic loop中 LLM 返回后，将思考内容、工具调用指令、工具结果写入 memory-store
- 写入失败不重试，记录日志
- 用户消息和 agent 的回复由消息通道组件推送到 memory-store，不由记忆写入器处理

### 7. 管理命令路由器
- 识别以特定前缀开头的外部消息（管理命令）
- 检查发送者是否在管理权限用户列表中
- 解析命令类型：绑定/解绑通道、管理权限管理、模式和角色切换、重新进入事件、列出事件、重置上下文
- 调用对应处理器执行命令

### 8. 模式管理器
- 维护当前模式状态（角色模式/事件模式）
- 默认角色模式
- 管理命令可切换模式，切换时通知协调器触发上下文重建
- 角色模式可查看所有记录，事件模式只查看本事件记录
- 进入事件模式时自动生成新事件标识

### 9. Station 路由表
- 从配置管理器读取已配置的 Station 列表
- 提供按 Station ID 查找地址的查询接口

### 10. Station 通信客户端
- 向 Station 发起请求（工具名称和参数）
- 从响应中获取工具调用结果
- 管理 Station 的连接超时配置

### 11. 通信客户端
- 作为客户端连接消息通道的服务端
- 连接后获取通道信息并发送绑定请求绑定用户
- 可连接多个通道（不同 messenger ID），每个连接独立维护
- 上行消息送入协调器，下行消息按 messenger ID 选择对应连接发送
- 支持心跳检测和断线自动重连

### 12. 工具调用分派器
- 解析 LLM 返回中的 tool call
- 区分内置工具和外置工具
- 内置工具由 nexus 自身执行，不发送 station，不记入记忆
- 外置工具通过 Station 路由表查找目标 Station，分派执行

### 13. 管理 API 服务器
- 绑定指定端口等待连接
- 供管理界面通过 API 对接配置管理

## 功能流程

### Epic 1 外部输入处理流程

```
通信模块收到消息
  → 检查消息来源和所属群组是否在绑定群组列表中
    ├─ 否 → 丢弃
    └─ 是 → 继续
  → 检查自回显标记
    ├─ 标记为自己发出的回显 → 对比发送记录确认后丢弃
    └─ 非自回显 → 进入命令检查
  → 管理命令路由器检查是否以管理命令前缀开头
    ├─ 是 → 检查发送者是否在管理员列表中
    │   ├─ 是 → 执行管理命令，回复执行结果，如需要则触发上下文重置
    │   └─ 否 → 回复无权限
    └─ 否 → 进入agentic loop
```

### Epic 2+3 agentic loop流程

```
普通消息 → 追加到上下文构建器的当前上下文
  → 检查上下文消息数量是否超过上限
    ├─ 是 → 触发自动重置（清除上下文，重新读取历史）
    └─ 否 → 继续
  → LLM 客户端调用 LLM API（传入当前完整上下文）
  → LLM 返回回复
    → 记忆写入器推送思考内容到写入队列
    → 通信模块发送回复到消息通道
  → 等待下一条输入
```

### 启动流程

```
kissbot-agent 启动
  → 加载配置文件，初始化配置管理器
  → 初始化模式管理器（默认角色模式）
  → 初始化记忆写入器（启动后台写入任务）
  → 初始化记忆读取器
  → 初始化上下文构建器
  → 初始化 LLM 客户端
  → 初始化通信模块（连接所有配置的通道，获取通道信息并绑定用户）
  → 记忆读取器按当前模式读取历史
  → 上下文构建器用历史 + Ego 信息构建初始上下文
  → 协调器进入就绪状态
```

### Epic 3 上下文重置流程

```
触发条件：重置命令 / 上下文超长
  → 记忆写入器刷新当前剩余内容到 memory-store
  → 记忆读取器按当前模式重新读取最近记录
  → 协调器从 memory-ego 重新加载自我认知信息
  → 上下文构建器重建上下文
```

### Epic 4 事件管理流程

```
进入事件模式 → 模式管理器生成新事件标识，切换为事件模式
  → 触发上下文重置，读取当前事件上下文（空）且只记录本事件
重新进入指定事件 → 切换到指定事件模式
  → 读取该事件的记录，重建上下文
列出事件 → 通过 memory-store 查询所有事件列表
切换回角色模式 → 重建上下文
```

## 关键设计

### 记忆模式隔离规则

- 角色模式：记忆读取器读取该角色下所有记录（包括各事件期间的记录）
- 事件模式：记忆读取器只读取本事件的记录
- 切换模式时重新读取并重建上下文

### 管理命令说明

| 命令类别 | 用途 |
|---------|------|
| 绑定/解绑 | 绑定或解绑指定通道的用户 |
| 管理权限管理 | 添加或移除用户的管理权限 |
| 角色切换 | 切换到指定角色 |
| 模式切换 | 在事件模式和角色模式间切换 |
| 重新进入事件 | 按事件标识重新进入指定事件 |
| 列出事件 | 列出所有事件 |
| 重置 | 重置当前上下文 |

### 自回显消息处理

- 带有自回显标记的消息是 agent 自己发出的消息经通道返回的回显
- 通过上下文构建器保存的已发送记录列表对比确认后丢弃
- 相关记忆已由记忆写入器写入，无需额外处理

### 自动上下文重置

当上下文消息数量超过上限时自动触发重置，防止 LLM token 占用无限增长。
