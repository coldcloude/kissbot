# kissbot-agent-station 模块设计

## 概述

Station 是 Agent 组件中的「行动」模块，负责持有工具并执行工具调用。它不直接与模型通信，也不读写记忆与上下文；对 Agent 的另一个模块 Nexus 只暴露两个能力：按会话的工具分组范围提供工具定义、按工具名执行工具并返回结果。

Station 同时是 MCP 服务端与 MCP 客户端：作为服务端，它对外提供工具发现与调用，可被任何 MCP 客户端（包括上级 Station）调用；作为客户端，它把每个直接子 Station 当作 MCP 服务端接入，把整棵子树的工具聚合到本级。因此 Station 可以组织成树，部署在服务器、网络设备、智能家电、机器人等不同形态的设备上，各自提供本地的工具。

## 核心功能

### Epic 1：工具注册与分组

- **目标**：按配置声明启用哪些工具分组，由内置注册表成对提供工具元数据与本地实现，并保证本级对外工具名唯一
- **依赖**：kissbot-mcp（工具定义与结果结构）、配置管理（本级配置）
- **用户故事**：
  - 作为一个管理员，我要在配置中声明启用哪些工具分组，以圈定本级提供的工具范围
  - 作为一个管理员，我要直接获得内置分组提供的工具，以使用常用能力
  - 作为一个外部系统（工具实现方），我要为本地工具提供实现，以让智能体在本机执行该工具
  - 作为一个管理员，我要让工具在执行后回填被规范化的参数，以让记忆与上下文记录实际生效的参数

### Epic 2：MCP 服务端

- **目标**：对外提供 MCP 服务（服务发现、工具列表、工具调用），并在入口处防止级联成环
- **依赖**：Epic 1（工具注册与分组）、kissbot-mcp
- **用户故事**：
  - 作为一个外部系统（上级 Station 或 MCP 客户端），我要把 Station 当作 MCP 服务端调用，以复用其工具能力
  - 作为一个外部系统（MCP 客户端），我要查询工具定义，以把工具交给语言模型选择调用
  - 作为一个外部系统（MCP 客户端），我要读取每个工具携带的分组，以按分组圈定可用工具范围
  - 作为一个管理员，我要限制 Station 端点的访问来源，以控制能力暴露范围

### Epic 3：子 Station 级联与兼容

- **目标**：把直接子 Station 作为 MCP 服务端接入，级联聚合与转发调用，携带祖先链避免成环，并在固定接入约定内接入不理解 kissbot 扩展的第三方 MCP 服务端
- **依赖**：Epic 2（子 Station 自身是 MCP 服务端）、kissbot-mcp
- **用户故事**：
  - 作为一个管理员，我要把多个 Station 组织成树形结构，以组合多台设备上的工具
  - 作为一个管理员，我要为子站配置命名前缀，以避免与其他节点的工具重名
  - 作为一个管理员，我要把第三方 MCP 服务端挂为子节点，以在符合本级接入约定的前提下复用其工具
  - 作为一个外部系统（上级 Station），我要在级联时携带祖先链，以避免循环调用

### Epic 4：工具发现与分组过滤

- **目标**：聚合本级与直接子的工具定义并保证顺序稳定，在 Agent 入口按会话的分组白名单过滤
- **依赖**：Epic 1（工具注册与分组）、Epic 3（子 Station 级联与兼容）
- **用户故事**：
  - 作为一个外部系统（MCP 客户端），我要一次拿到整棵直接子树的工具定义，以自行决定使用范围
  - 作为一个管理员，我要为不同会话启用不同的工具分组，以控制智能体可用的工具范围
  - 作为一个管理员，我要在某个会话不启用任何分组时让模型请求不携带工具，以兼容纯对话场景

### Epic 5：工具执行与失败隔离

- **目标**：按工具名在本级实现与直接子 Station 之间路由并执行；单个子站不可用不影响其他工具与启动
- **依赖**：Epic 1、Epic 3
- **用户故事**：
  - 作为一个用户，我要让智能体执行工具任务，以完成具体的操作
  - 作为一个用户，我要让智能体使用下级 Station 上的工具，以完成需要其他设备参与的任务
  - 作为一个管理员，我要在一个子站不可达时仍能使用本级与其他子站的工具，以保证可用性

## 模块划分

- **Station（单例）**：进程内唯一的工具主机，持有本站标识、本级工具集合、直接子站连接、工具路由、子站访问凭据与服务端身份
- **工具实现接口**：本地工具的统一入口，接收结构化参数，返回可能被改写的参数与工具结果
- **工具条目与分组**：工具条目的形态（元数据 + 实现）与分组的组织方式；内置注册表按分组名成对产出工具元数据与实现
- **子站运行态**：每个直接子站一个 MCP 客户端；连接参数按子站标识从配置现读，不在运行态保存
- **工具路由**：工具名到直接子站标识的映射，只服务工具调用，每次工具发现时整体重建
- **station MCP 端点**：把 Station 挂到独立的对外端点，实现服务发现、工具列表与工具调用；认证由安全库中间件叠加
- **内置注册表**：当前提供文件系统分组与读取文件的工具

## 功能流程

### 启动流程

```
读取本级配置（本站标识、分组集合、直接子站集合）
  → 逐项注册：为每个分组注册内置注册表提供的工具（未内建的分组只有名字）
  → 为每个已启用的直接子站建立 MCP 客户端
  → 注册为进程级单例
  → 单独启动 station MCP 端点
```

### 工具发现流程

```
收到工具列表请求（可带祖先链）
  → 本站标识已在祖先链中：返回协议级错误（级联成环）
  → 收集本级工具（每个工具带所属分组）
  → 对每个已启用的直接子站实时查询工具列表（祖先链追加本站标识）
      ├─ 成功：工具名按该子站前缀加前缀；分组取对端携带的分组，未携带则归入该子站默认分组
      └─ 失败：记录告警并跳过该子站
  → 合并：本级优先；重名的后到者剔除
  → 用本次结果整体替换工具路由
  → 按工具名排序后返回
```

### 工具调用流程

```
收到工具调用请求（工具名 + 参数 + 祖先链）
  → 本站标识已在祖先链中：返回协议级错误
  → 本级工具集合命中：执行本地实现，返回（回收的参数 + 工具结果）
  → 未命中：查工具路由
      ├─ 未命中：返回协议级「工具不存在」错误
      └─ 命中直接子站：按配置取该子站前缀、剥去前缀、带上祖先链转发
          ├─ 子站返回正常结果（含工具自身判定的失败）：原样回传
          ├─ 子站返回协议级错误：原样透传
          └─ 传输或解码失败：包装为协议级内部错误
```

### 运行期增删流程

```
管理员调用管理 API
  → 先写配置，写失败即返回、不改运行态
  → 新增分组：只注册该分组的工具
  → 移除分组：只注销该分组的工具
  → 启用子站：按该子站配置建立 MCP 客户端
  → 停用子站：拆除该子站的 MCP 客户端
  → 子站集合变化后清空工具路由，由下一次工具发现重建
```

### 内置工具流程

```
收到读取文件请求
  → 参数缺失：返回失败结果
  → 把路径规范化为真实绝对路径（相对路径以进程工作目录为基准）
  → 校验规范化结果位于工作目录内
  → 读取文本内容，超过长度上限时截断
  → 返回单个文本内容块
```

## 关键设计

### 工具名对外唯一

工具调用只携带工具名，因此本级对外工具名必须唯一。本级以工具名为键维护工具集合，重复注册保留先到者并告警；级联合并时本级优先于所有子站，子站之间保留先出现者。由于子站集合的遍历顺序不固定，两个子站提供同名工具时，每次启动归属哪一个子站不保证一致，因此多个子站应通过命名前缀避免重名。

### 分组是工具的属性

分组在工具注册时确定，随工具定义对外携带，服务端不做分组过滤。会话按分组白名单圈定范围这件事发生在 Agent 入口：白名单为空即无工具，聚合结果为空时模型请求不携带工具定义。白名单不下传子站。

### 失败隔离

子站在工具发现阶段不可达只影响该子站：本次它的工具不可见、路由失效，其余工具与启动不受影响。聚合结果为空是合法结果而非错误。子站在调用阶段不可达则只让这一次工具调用失败。

### 祖先链防环

发现与调用都携带「根到当前父节点」的站点标识链，本级处理时把自己的标识追加进去再转发。任一层发现自己的标识已在链中即拒绝，从而在级联配置成环时不会无限递归。祖先链是纯提示信息：不理解该扩展的对端只会看到一个被忽略的未知元信息键。

### 兼容第三方 MCP 服务端

子站不要求是 kissbot Station，也不要求声明任何 kissbot 能力：只要对端按本级固定的接入约定提供 MCP 服务（单端点 HTTP 请求-响应、协议版本与本实现一致、接受或忽略本级发送的业务密钥），就能作为直接子站接入。分组归因按「对端携带分组就用它，未携带则归入该子站的默认分组」处理，因此这类服务端的工具同样能被会话白名单圈定；子站返回的工具级失败结果原样回传，不被解释或改写。

接入约定是固定的，本级不与子站协商：不查询对端能力、不协商协议版本、不更换传输形态与认证方式。使用其他传输方式（如标准输入输出）、以事件流返回响应、要求会话标识、使用其他协议版本、或要求其他认证凭据的 MCP 服务端，不能直接作为子站接入。

### 运行态不保存配置

Station 运行态只保存本站标识、工具集合、子站客户端、工具路由与子站访问凭据；分组集合与子站连接参数每次使用时从配置读取。这样配置是唯一来源，不会出现配置与运行态两份不一致；代价是每次工具发现与调用都会读取一次配置。

### 顺序稳定

工具列表按工具名排序后返回，使同一集合多次请求得到相同顺序，便于调用方与提示词侧保持稳定。分组集合按固定顺序保存，本级工具的注册顺序因此可复现。

### 只做逐项增删

运行期只在被修改的那一项上增删运行态（某个分组的工具、某个子站的客户端），不做整份重载。全量重载只有重启进程一种方式；子站的增删与连接参数修改也只能改配置后重启。
