# kissbot-channel-client 组件设计

## 概述

kissbot-channel-client 是通道客户端库，以程序库形式供 agent 使用（附带的命令行客户端是一个独立程序）。它把与通道服务端的连接、请求-响应、事件回调与附件传输封装为可直接调用的能力，调用方只需实现回调接口即可接入任意通道实现。

## 核心功能

### Epic 1：连接与请求响应

- **目标**：建立并维护与通道服务端的长连接，把各类操作表达为请求-响应
- **依赖**：kissbot-channel（服务端协议）、kissbot-security（密钥）
- **用户故事**：
  - 作为一个外部系统（agent），我要用通道地址与密钥建立连接，以接入该通道
  - 作为一个外部系统（agent），我要主动断开连接，以停止接收消息
  - 作为一个外部系统（agent），我要在请求超时或服务端返回错误时得到明确错误，以决定是否重试或重连

### Epic 2：回调接口

- **目标**：向调用方提供接收上行消息、群组事件、用户删除、附件数据与连接关闭的回调
- **依赖**：Epic 1
- **用户故事**：
  - 作为一个外部系统（agent），我要在收到上行消息时得到通知与「以谁的身份收到」，以正确归属该消息
  - 作为一个外部系统（agent），我要在用户加入或退出群组时得到通知，以更新通道状态
  - 作为一个外部系统（agent），我要在用户被删除时得到通知，以清理相关状态
  - 作为一个外部系统（agent），我要在连接关闭时得到通知，以决定何时重连
  - 作为一个外部系统（agent），我要在附件分块到达时决定是否确认，以控制下载进度

### Epic 3：绑定与消息收发

- **目标**：把连接绑定到具体身份，并在绑定后收发消息、查询通道信息
- **依赖**：Epic 1、Epic 2
- **用户故事**：
  - 作为一个外部系统（agent），我要绑定通道上的用户身份，以接收该身份的消息
  - 作为一个外部系统（agent），我要解绑不需要的身份，以停止接收
  - 作为一个外部系统（agent），我要发送消息并取得服务端生成的消息标识与时间，以用于回显识别与记忆记录
  - 作为一个外部系统（agent），我要查询通道的用户与群组信息，以选取绑定身份

### Epic 4：附件上传与下载

- **目标**：把附件分块上传与分块下载封装为一次调用，向调用方隐藏分块与传输标识的细节
- **依赖**：Epic 3
- **用户故事**：
  - 作为一个外部系统（agent），我要把一个文件随消息上传，以发送附件
  - 作为一个外部系统（agent），我要按存储标识下载附件，以取得文件内容
  - 作为一个外部系统（agent），我要按块处理下载数据，以避免把整个文件读入内存

### Epic 5：命令行调试客户端

- **目标**：提供一个可手工操作通道的客户端程序，用于联调通道实现与观察消息流转
- **依赖**：Epic 1~4
- **用户故事**：
  - 作为一个开发者，我要以指定身份登录通道，以模拟一个 agent
  - 作为一个开发者，我要手动发送文本、上传文件、下载附件，以验证通道实现的行为
  - 作为一个开发者，我要在终端看到上行消息与群组事件，以确认消息是否被投递

## 模块划分

- **客户端**：连接管理、请求-响应（序号关联与超时）、事件处理器注册、附件下载状态维护
- **回调接口**：调用方需要实现的接收侧能力
- **附件传输**：二进制分块的组帧与确认、下载数据的接收与交接
- **命令行客户端**：参数解析、配置读取、交互命令与输出

## 功能流程

### 接入流程

```
读取通道地址与密钥 → 建立连接 → 查询通道信息 → 按身份绑定 → 开始收发
连接关闭回调 → 上层决定是否重建连接 → 重建后重新绑定
```

### 发送流程

```
调用方给出目标身份与内容 → 发送请求 → 等待响应（超时则报错）
  → 附件：服务端完成注册并返回传输标识 → 按块上传并逐块确认
  → 成功返回消息标识、时间与转换后的内容
```

### 接收流程

```
服务端推送帧到达 → 按帧类型分派到对应处理器
  → 上行消息 / 群组事件 / 用户删除：调用回调
  → 附件分块：登记到下载状态表后调用回调，并按回调结果回发确认
```

### 命令行客户端流程

```
按参数确定身份与群组并绑定 → 逐行读取输入
  → 普通文本：发送到当前群组
  → 切换群组 / 下载附件 / 上传附件 / 强制按文本发送
  → 打印收到的上行消息与事件
```

## 关键设计

### 回调而非轮询

客户端把收到的推送直接交给调用方实现的回调，不在内部排队。调用方因此可以按自己的节奏处理消息；回调返回的结果（下载确认）也会被回传给服务端，从而让下载进度由调用方控制。

### 回调带客户端标识

所有回调的第一个参数是「触发事件的客户端标识」。这样一个回调实现就可以同时服务多个连接或身份，而不必为每个连接创建一个对象。

### 超时与错误显式化

每个请求都有超时，服务端返回错误状态时会转为错误结果；因此调用方可以区分「请求没发出去」「请求超时」「服务端拒绝」三种情况，并决定重连或重试。客户端本身不做自动重试，也不做自动重连。

### 附件分块对调用方透明

上传把文件切成固定大小的块依次发送并逐块确认；下载把收到的块交给回调并回发确认。调用方只看到「上传一个文件」「收到一段数据」，不需要理解传输标识与分块位置。

### 连接与身份解耦

连接是传输层概念，身份是通道上的用户。一个连接可以绑定多个身份，一个身份只能被一个连接绑定。重连会建立新连接，因此必须重新绑定；客户端不保存绑定关系，避免出现「以为已绑定实际未绑定」的隐蔽状态。

### 命令行客户端是调试工具

命令行客户端只实现最小交互：以固定身份接入、按行发送、手动上传下载。它不追求完整功能，目的是在开发与联调时快速验证通道实现与协议行为。
