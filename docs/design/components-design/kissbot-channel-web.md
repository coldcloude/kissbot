# 通道实现模块（Web）

## 概述

Web 消息通道的实现。作为独立服务运行，实现 Messenger 接口，提供基于 Web 的即时通讯功能。
包含后端服务（Rust）和前端界面（React）两部分。

**用户模型**：
- **管理用户（admin）**：唯一的外部用户，通过 admin 密钥认证接入 Web 前台
- **普通用户（users）**：由 nexus 代表的智能体身份，可与管理员私聊或群聊。所有 user 共用 user 密钥
- Admin 和 users 在配置文件中定义，agent 与 user 的绑定由 kissbot-channel 的 nexus 绑定流程动态建立

**默认群组**：添加 user 时自动创建该 user 与 admin 的单聊群组。

## 后端 — kissbot-channel-web

进程内运行通道管理器（kissbot-channel 库提供），注册一个 WebMessenger 实现，通过 Messenger 接口交互，持续运行。

### 核心功能

#### Epic 1：消息收发
- **目标**：通过 API 接收 admin 的 Web 消息和附件，转发到对应 agent 群组；接收 agent 回复，实时推送到 Web 界面
- **依赖**：kissbot-channel（Messenger 接口、通道管理器）、安全认证模块
- **用户故事**：
  - 作为一个管理员，我要在 Web 界面向某个群组发送文本消息，以使消息路由到该群组绑定的所有 agent
  - 作为一个管理员，我要在 Web 界面上传附件（图片/文件），以使附件保存到本地文件系统并在消息中携带附件 key
  - 作为一个管理员，我要在收到 agent 回复时不需手动刷新页面，以使实时推送机制将消息送达 Web 界面
  - 作为一个管理员，我要在 Web 界面上看到自己已发送的消息标记为已发送，以区分自己发出的消息和他人消息
  - 作为一个管理员，我要查看历史消息，以回顾之前的对话内容

#### Epic 2：群组管理
- **目标**：群组的创建、修改、删除，以及群组成员管理
- **依赖**：kissbot-channel（Messenger 接口、通道管理器）
- **用户故事**：
  - 作为一个管理员，我要在 Web 界面新建群组，以指定群组名称和成员列表
  - 作为一个管理员，我要修改群组名称，以更新群组信息
  - 作为一个管理员，我要添加或移除群组成员，以触发群组变化回调通知 nexus
  - 作为一个管理员，我要删除群组（admin-user 单聊群组不可删除），以清理群组数据并通知 nexus
  - 作为一个管理员，我要在 admin-user 单聊群组中仅可查看消息，以限制对该类群组的操作

#### Epic 3：用户管理
- **目标**：普通用户的创建和删除，自动生成与 admin 的单聊群组
- **依赖**：kissbot-channel（Messenger 接口、群组变化回调、用户删除回调）
- **用户故事**：
  - 作为一个管理员，我要在 Web 界面新建用户，以使系统写入配置文件并自动创建该用户与 admin 的单聊群组
  - 作为一个管理员，我要修改用户名，以更新配置文件中的用户信息
  - 作为一个管理员，我要删除用户，以移除用户及其所有单聊群组并触发用户删除回调通知通道管理器

#### Epic 4：附件存储与管理
- **目标**：提供本地文件系统附件存储能力，支持附件上传、下载和缩略图生成
- **依赖**：无
- **用户故事**：
  - 作为一个管理员，我要上传图片，以使附件保存到本地文件系统并自动生成缩略图，接口返回附件 key
  - 作为一个管理员，我要上传文件，以使附件保存到本地文件系统并标记无缩略图，接口返回附件 key
  - 作为一个管理员，我要按附件 key 下载附件，以获取文件数据
  - 作为一个管理员，我要查看缩略图，以按附件 key 获取图片缩略图（非图片文件不返回缩略图）
  - 作为一个管理员，我要查询附件的元数据（文件名、类型、大小、缩略图信息），以了解附件详情

#### Epic 5：配置持久化与管理
- **目标**：应用配置从文件加载，运行时群组和用户的变更自动写回配置文件
- **依赖**：无
- **用户故事**：
  - 作为一个 Web 通道服务，我要在启动时从配置文件加载 messenger ID、admin 密钥、user 密钥、用户列表和群组列表，以初始化运行状态
  - 作为一个管理员，我要在 Web 界面进行群组和用户变更操作，以使变更同步写回配置文件保证重启后不丢失
  - 作为一个管理员，我要更改 admin 用户的显示名称，以更新管理界面的标识

### 模块划分

WebMessenger 是 Messenger 接口的实现，内部持有以下模块：

#### 1. 配置管理器
加载配置文件，解析 admin、users、groups 定义。加载时自动注入默认私聊群组（每个 user 与 admin 的单聊）。管理员在 UI 中新建/编辑/删除群组时同步写回配置文件。提供运行时读取和修改群组的方法。

#### 2. 群组管理器
维护群组实体（配置群组 + 自动生成的 admin-user 单聊群组）和构建 Messenger 视角的用户-群组映射。

**消息发送**：通道管理器按 (用户, 群组) 组合分发下行消息，群组管理器根据群组成员列表遍历所有绑定的 user。

**权限控制**：admin 在群组中时消息收发权限和普通 user 一致。web 界面额外向 admin 提供群组变更功能。

#### 3. 用户管理器
维护普通用户列表（不包含 admin）。新增用户时写入配置文件，自动生成该 user 与 admin 的单聊群组。删除用户时从配置文件中移除用户及其单聊群组，触发用户删除回调。

#### 4. Web 通道（消息收发通道）
每 (用户, 群组) 组合对应一个 Web 通道。实现消息发送方法将消息实时推送给前端。注册消息到达回调处理前端发来的消息。发送时根据消息的群组类型，确定消息的目标用户是自己还是对方。

#### 5. 附件存储器
使用本地文件系统存储附件。实现附件元数据查询和数据读取。上传时图片自动生成缩略图。按附件 key 提供下载和缩略图接口。

#### 6. API 服务器
提供 REST API 和实时推送长连接。所有请求通过安全认证模块统一认证。支持跨域访问。

#### 7. 实时推送分发器
管理长连接列表，按群组 ID 推送实时消息。每个连接对应一个群组的消息流，支持断线重连。

### 功能流程

#### Epic 1 消息上行（admin → agent）
1. 管理员在 Web UI 中选择群组，发送消息（可携带附件）
2. Web UI 通过 API 发送到消息发送接口
3. WebMessenger 接收消息：如有附件则保存到附件存储器，生成全局唯一 key
4. 群组管理器确定群组成员（遍历所属 user 列表）
5. 通过 Messenger 回调通知通道管理器，逐 user 处理
6. 通道管理器后续处理（消息入队、推送等）

#### Epic 1 消息下行（agent → admin）
1. 通道管理器按 messenger ID、群组 ID 和用户 ID 查找 Web 通道，调用消息发送方法
2. Web 通道通过实时推送分发器将消息推送至 Web UI
3. 管理员收到回复

#### Epic 2 群组创建流程
1. 管理员在 Web UI 新建群组（指定名称和成员）
2. API 请求到群组创建接口
3. 群组管理器创建群组：写入配置文件加入内存，触发群组变化回调
4. 后续由通道管理器处理通知和绑定

#### Epic 2 群组删除流程
1. 管理员在 Web UI 选择群组删除（admin-user 单聊群组不可删除）
2. API 请求到群组删除接口
3. 群组管理器校验后从配置文件和内存中移除，移除对应的所有 Web 通道实例，触发群组变化回调
4. 后续由通道管理器处理通知和清理

#### Epic 3 用户创建流程
1. 管理员在 Web UI 新建用户（指定用户名）
2. API 请求到用户创建接口
3. 用户管理器写入配置文件和内存
4. 群组管理器自动创建该 user 与 admin 的单聊群组
5. 触发群组变化回调通知 nexus

#### Epic 3 用户删除流程
1. 管理员在 Web UI 选择用户删除
2. API 请求到用户删除接口
3. 用户管理器从配置文件和内存中移除用户
4. 群组管理器移除相关的单聊群组
5. 触发用户删除回调通知通道管理器

#### Epic 4 附件上传流程
1. 管理员在 Web UI 选择文件/图片上传
2. 上传请求到附件上传接口
3. 附件存储器保存文件到本地文件系统
4. 如果是图片，自动生成缩略图
5. 返回附件 key（用于后续消息引用）
