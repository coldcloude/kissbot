# kissbot-config 组件设计

## 概述

公共配置组件，以程序库形式被各组件引用。它只读加载一份公共配置文件，按点号路径提供层级化的配置读取接口，不约定具体的配置块结构。不同组件进程可以读取同一份配置文件，从而在服务地址、密钥等共享配置上保持一致。

## 核心功能

### Epic 1：公共配置的加载

- **目标**：在首次访问时加载公共配置文件，并在整个进程中只保留一份解析结果
- **依赖**：无
- **用户故事**：
  - 作为一个管理员，我要通过环境变量指定配置文件位置，以在不同部署中复用同一套程序
  - 作为一个管理员，我要在未指定位置时使用默认路径，以直接启动各组件
  - 作为一个管理员，我要在配置缺失或格式错误时立即看到启动失败，以尽早发现配置问题

### Epic 2：层级化配置读取

- **目标**：按点号路径导航到配置的任意层级，并把该层内容解析为调用方定义的类型
- **依赖**：Epic 1（公共配置的加载）
- **用户故事**：
  - 作为一个外部系统（组件进程），我要按路径读取自己需要的配置段，以获取服务地址、监听端口等运行参数
  - 作为一个外部系统（组件进程），我要以自定义类型接收配置段，以按自己的需要组织配置结构
  - 作为一个管理员，我要在一次配置文件中集中维护各组件的公共配置，以统一修改与部署

## 模块划分

- **配置单例**：负责读取并解析配置文件，在进程内仅加载一次
- **访问接口**：按路径导航与反序列化；路径不存在或类型不匹配时终止进程

## 功能流程

```
组件首次访问配置
  → 确定配置文件路径（环境变量优先，否则默认路径）
  → 读取并解析配置文件
  → 存入进程级单例
  → 调用方给出路径，逐层导航到目标节点
  → 把目标节点反序列化为调用方定义的类型并返回
```

## 关键设计

### 只读与单次加载

配置只在首次访问时加载一次，此后不读取文件，也不提供修改能力。组件因此不会因为配置文件的运行期变化而产生不一致的运行态；需要变更配置时重启进程。

### 结构由使用方决定

组件不约定配置块的结构，只做路径导航与类型转换。每个组件用自己定义的类型读取自己的配置段，新增配置块或调整块内结构不需要修改本组件。

### 快速失败

配置文件不存在、无法解析、路径不存在或类型不匹配时立即终止进程。配置错误在启动阶段暴露，而非在运行期以默认值掩盖。

### 共享配置的边界

组件只负责提供读取能力；哪些配置项属于公共配置、哪些属于各组件可修改并持久化的配置，由使用方决定。共享的服务地址与密钥放在公共配置中，各组件的业务配置由各组件自行管理。
