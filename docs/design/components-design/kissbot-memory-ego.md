# kissbot-memory-ego 组件设计

## 概述
自我认知模块，作为独立服务运行，管理 agent 的双重自我认知设定（客观设定和角色设定）。提供 Agent 元数据、个体识别信息、角色扮演设定等数据的存储、查询和搜索能力。独立于 nexus 模块，与其他记忆模块共享同一文件系统。

## 核心功能

### Epic 1：Agent 元数据管理
- **目标**：管理每个 agent 的身份标识信息，包括个体名称、描述、创建时间等，支持创建、查询、更新和复制
- **依赖**：kissbot-memory（目录管理）
- **用户故事**：
  - 作为一个管理员，我要创建一个 agent，以分配唯一的 agent ID 并写入身份标识信息
  - 作为一个管理员，我要查询 agent 的元数据，以查看其身份标识信息
  - 作为一个管理员，我要列出所有已有 agent，以了解系统中全部 agent 的概况
  - 作为一个管理员，我要修改 agent 的名称，以更新其身份标识
  - 作为一个管理员，我要修改 agent 的描述，以更新其功能说明
  - 作为一个管理员，我要复制一个 agent 的元数据，以基于现有配置快速创建新 agent

### Epic 2：个体识别信息管理
- **目标**：管理 agent 认知的外部个体信息，包含个体身份标识、个体间关系等，支持增删改查
- **依赖**：Epic 1（Agent 元数据）
- **用户故事**：
  - 作为一个管理员，我要为 agent 添加外部个体，以设置该个体的名称、身份识别信息和与其他个体的关系
  - 作为一个管理员，我要查询 agent 认知的所有外部个体，以了解 agent 能识别哪些外部角色
  - 作为一个管理员，我要批量替换个体列表，以在一次操作中移除旧个体并添加新个体
  - 作为一个管理员，我要重命名个体，以更新 agent 识别信息中的个体名称

### Epic 3：角色设定管理
- **目标**：管理 agent 的角色扮演设定，支持一个 agent 拥有多份独立角色设定，包含角色描述、角色间关系等功能
- **依赖**：Epic 1（Agent 元数据）
- **用户故事**：
  - 作为一个管理员，我要为 agent 创建新角色，以指定角色名称和角色描述
  - 作为一个管理员，我要查询 agent 的所有角色列表，以了解 agent 可扮演的全部角色
  - 作为一个管理员，我要按角色名称查询单份角色设定，以获取完整的角色信息
  - 作为一个管理员，我要修改角色名称，以更新角色的标识
  - 作为一个管理员，我要修改角色描述，以更新角色的行为说明
  - 作为一个管理员，我要删除角色，以从文件系统中移除对应的角色设定
  - 作为一个管理员，我要为角色添加其他角色关系，以定义该角色与其他角色的关联
  - 作为一个管理员，我要修改角色间关系的个体名称、关系描述和关系类型，以更新角色关联信息

### Epic 4：全文搜索与自动补全
- **目标**：对 agent 元数据和角色设定信息提供搜索和自动补全能力
- **依赖**：Epic 1（Agent 元数据）、Epic 3（角色设定）
- **用户故事**：
  - 作为一个管理员，我要按名称搜索 agent，以找到名称匹配的 agent
  - 作为一个管理员，我要按描述搜索 agent，以找到名称或描述匹配的 agent
  - 作为一个管理员，我要输入 agent 名称前缀获取补全建议，以快速定位 agent
  - 作为一个管理员，我要按名称搜索角色，以在指定 agent 下找到名称匹配的角色
  - 作为一个管理员，我要启动自我认知服务，以保证搜索功能立即可用
  - 作为一个管理员，我要修改 agent 元数据或角色数据，以保证搜索结果始终准确

### Epic 5：自我认知信息读取 API
- **目标**：为 nexus 提供读取 agent 自我认知信息的接口，包括身份标识、个体识别和角色扮演信息
- **依赖**：Epic 1~4
- **用户故事**：
  - 作为一个外部系统（nexus），我要在启动时获取 agent 的元数据（名称、描述），以构建 LLM 系统消息中的身份信息
  - 作为一个外部系统（nexus），我要获取指定 agent 的外部个体信息，以让智能体识别对话方身份
  - 作为一个外部系统（nexus），我要获取指定 agent 和角色的扮演信息（角色描述、关联个体、角色间关系），以构建 LLM 系统消息中的角色设定

## 内部模块

### 1. Agent 元数据管理器
- 管理 agent 元数据文件的存储和读取
- 支持 agent 的创建、查询、更新、复制、搜索
- 使用缓存机制实现并发安全的懒加载

### 2. 个体识别信息管理器
- 管理个体识别信息文件的读写
- 提供个体信息的增删改查、重命名、批量替换
- 管理个体标识、权限、个体间关系

### 3. 角色设定管理器
- 管理角色设定文件的读写
- 提供角色设定的创建、查询、更新、删除、复制、重命名
- 管理角色与个体的关系、角色间关系
- 使用两级映射实现细粒度并发控制

### 4. 搜索管理器
- 实现搜索和自动补全功能
- 脏标记机制延迟更新搜索索引
- 启动时自动加载所有 agent 和角色的数据到搜索索引
- 支持按 agent 过滤的角色搜索
- **Agent 搜索**：`name_index` 为 `individual_name -> agent_id` 全匹配（HashMap），`search_by_name` 返回 `Option<String>`（最多一个）；`name_completion`（individual_name 前缀补全）与 `name_descr_index`（[individual_name, description] 子串）保留
- **Role 搜索**：`role_name_index`（role_name 子串）与 `role_name_completion`（role_name 前缀）不变；`role_name_descr_index` 索引 `[role_name, full_name, description]`（full_name 为展示文本）

### 5. API 服务器
- Agent 元数据管理接口：创建、查询、更新名称/描述、复制、搜索（search-name 全匹配返回 Option）、名称补全、批量获取
- 个体识别信息管理接口：查询全部/单个个体、批量替换个体/标识/关系、重命名个体
- 角色设定管理接口：列表、查询、创建、复制、删除、重命名、更新描述/更新 full_name、搜索、名称补全；角色间关系增删改查
- 代号校验：`role_name`/`individual_name` 写入入口强制 `^[A-Za-z0-9_]+$`（非空）

## Agent 自我认知数据模型

### 客观设定（每个 agent ID 对应一份）
- **身份标识**：agent 的编号、个体名称、描述、创建时间、禁止事项和自主运行目标
- **个体识别信息**：个体列表，每项包含个体名称、身份识别（如所有者、管理员或其他个体）、个体所关联的消息通道身份、个体与其他个体的关系、个体描述

### 角色设定（每个 agent ID 对应多份）
- **角色扮演**：角色名称（代号）、full_name（展示文本）、角色描述和该角色的自主运行目标
- **角色间关系**：其他角色名称（代号）、该角色关联的个体名称（代号）、关系描述、关系类型；RoleRelation 含 full_name（展示文本）

## 功能流程

### Epic 1 Agent 元数据管理流程
管理员发送 API 请求 → Agent 元数据管理器处理 → 读取/写入 agent 目录下的元数据文件 → 同步搜索索引 → 返回结果。

### Epic 2 个体识别信息管理流程
管理员发送 API 请求 → 个体识别信息管理器处理 → 读取/写入 agent 目录下的个体识别信息文件 → 同步搜索索引 → 返回结果。

### Epic 3 角色设定管理流程
管理员发送 API 请求 → 角色设定管理器处理 → 读取/写入 agent 目录下的角色设定文件 → 同步搜索索引 → 返回结果。

### Epic 4 搜索流程
管理员发送搜索请求 → 搜索管理器按需同步索引 → 在索引中执行搜索 → 返回匹配结果列表。

### Epic 5 自我认知读取流程
nexus 启动或上下文重置时 → 通过 API 查询 agent 元数据和/或角色设定 → 返回结构化数据 → nexus 构建到 LLM 系统消息中。

## 关键设计

### 搜索索引维护
- 启动时自动加载所有 agent 和角色的数据到搜索索引，保证搜索功能立即可用
- 元数据或角色数据变更时同步更新索引，保证搜索结果始终准确

### 数据来源
- 基础模式：通过 API 手动填写设定文件
- 进阶模式（规划中）：结合配置信息和从记忆中提取的信息，自动生成设定
