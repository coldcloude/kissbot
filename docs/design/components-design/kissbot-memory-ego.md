# kissbot-memory-ego 组件设计

## 概述
自我认知模块，管理 agent 的双重自我认知设定。独立于 nexus 模块，与其他记忆模块共享同一文件系统。

## 核心功能

1. **Agent 元数据管理**：管理每个 agent 的身份标识和个体识别信息
2. **角色设定管理**：管理 agent 的角色扮演设定，支持一个 agent 拥有多份角色设定
3. **全文搜索**：对 agent 元数据和设定信息提供全文搜索能力

## 内部模块

### 1. AgentManager - Agent 元数据管理器
- 管理 agent 元数据文件的存储和读取
- 支持 agent 的创建、查询、更新、复制、搜索

### 2. IndividualRecognitionManager - 个体识别信息管理器
- 管理个体识别信息文件的读写
- 提供个体信息的增删改查
- 管理个体标识、权限、个体间关系

### 3. RolePlayManager - 角色设定管理器
- 管理角色设定文件的读写
- 提供角色设定的创建、查询、更新、搜索
- 管理角色与个体的关系、角色间关系

### 4. SearchManager - 全文搜索
- 使用倒排索引实现全文搜索
- 脏标记机制延迟更新搜索索引
- 启动时自动加载所有 agent 到搜索索引

### 5. HTTPS API 服务器
- Agent 元数据管理 API
- 个体识别信息管理 API
- 角色设定管理 API

## Agent 自我认知数据模型

### 客观设定（每个 agent ID 对应一份）
- **身份标识**：agent 的编号、个体名称、描述、创建时间、禁止事项和自主运行目标
- **个体识别信息**：个体列表，每项包含个体名称、身份识别（如所有者、管理员或其他个体）、个体所关联的消息通道身份、个体与其他个体的关系、个体描述

### 角色设定（每个 agent ID 对应多份）
- **角色扮演**：角色名称、角色描述和该角色的自主运行目标
- **角色扮演关系**：角色名称、关联的个体、角色与该个体的关系、角色与其他角色的关系、关系描述

## 功能流程

### 自我认知读取流程
nexus 启动或上下文重置时，查询自我认知模块 -> 读取 agent 的客观设定 -> 如果配置了角色设定，按角色名称读取对应的角色扮演信息 -> 将获取的自我认知信息构建到系统消息中 -> 进入 agentic loop。

### 数据来源
- 基础模式：通过 HTTPS API 手动填写设定文件
- 进阶模式（规划中）：结合配置信息和从记忆中提取的信息，自动生成设定
