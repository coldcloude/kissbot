# kissbot-memory-store 组件设计

## 概述
记忆存储模块，作为独立服务运行，收集 nexus 推送的全部原始消息（包括通道消息、思考内容、工具调用、工具结果），按统一格式持久化到文件系统。填充记忆系统的原始数据层，为记忆结构实现模块提供数据来源。

## 核心功能

### Epic 1：记忆记录写入
- **目标**：接收 nexus 推送的记忆记录，按统一格式持久化到文件系统，保证同一文件内记录有序
- **依赖**：kissbot-memory（记录类型定义、路径构造、目录管理）
- **用户故事**：
  - 作为一个外部系统（nexus），我要推送通道消息、思考、工具调用和工具结果四类记忆记录到记忆存储，以持久化推送的记忆记录，保证同一文件内的记录有序
  - 作为一个外部系统（nexus），我要在新记录时间早于文件最晚记录时请求强制写入，以处理非顺序到达的数据

### Epic 2：记忆记录查询
- **目标**：按时间范围查询四种类型的记忆记录，返回按时间排序的记录列表
- **依赖**：kissbot-memory（索引、记录类型定义）
- **用户故事**：
  - 作为一个外部系统（查询方），我要按时间范围和 agent、角色条件查询通道消息、思考、工具调用和工具结果四类记忆记录，以获取该时间段内按时间从前到后排序的记录列表

### Epic 3：新数据通知
- **目标**：新数据到达时通知所有已连接的记忆结构实现模块，触发其增量更新
- **依赖**：Epic 1（记忆记录写入）
- **用户故事**：
  - 作为一个外部系统（记忆结构实现模块），我要连接到记忆存储的通知服务器并维持长连接，以接收新数据到达的通知，触发增量更新

## 内部模块

### 1. 记录管理器
- 管理四种类型记录的存储和读取
- 按 agent、角色和日期自动创建目录和记录文件
- 支持批量追加记录（分配顺序编号、按时间排序、后写文件）
- 支持强制写入模式下的全量读取、排序重写
- 写入后通过回调通知索引模块标记脏数据

### 2. 索引配合层
- 记录写入后通知索引模块更新对应文件的索引
- 四种记录类型（通道消息、思考、工具调用、工具结果）各自独立维护索引状态

### 3. API 服务器
- 提供记忆写入接口和记忆查询接口

### 4. 通知服务器
- 接受记忆结构实现模块的连接
- 维护已连接的客户端列表
- 新数据到达时通知所有已连接客户端
- 支持心跳检测、连接管理

## 功能流程

### Epic 1 记忆写入流程
推送方将记录按类型分组 → 批量发送请求到记忆存储组件 → 记录管理器按 agent、角色、日期分组 → 获取文件级锁 → 读取文件尾获取最新顺序编号和时间 → 分配新编号 → 按时间排序后追加写入记录文件 → 触发回调标记索引脏 → 返回。

当允许强制写入且新记录时间顺序异常时的处理流程：获取文件级锁 → 读取整个文件所有记录 → 合并新旧记录 → 统一按时间排序 → 重新分配顺序编号 → 重写整个文件 → 标记索引全量脏 → 返回。

### Epic 2 记忆查询流程
查询方发送请求 → 记录管理器解析请求得到 agent、角色和时间范围 → 调用索引模块的对应查询方法 → 按天分段 → 反向读取每段记录文件 → 汇总排序 → 返回结果。

### Epic 3 新数据通知流程
记忆结构模块连接通知服务器 → 服务器注册客户端 → 新数据写入 → 服务器向所有注册客户端广播通知 → 客户端按需拉取新数据。

## 关键设计

### 记录写入规则
- 按 agent、角色、日期和类型组织文件并追加写入；每次写入分配递增的顺序编号，保证同一文件内记录有序
- 新记录时间早于文件最晚记录时检查是否允许强制写入：允许时全量读取重新排序写回，不允许时拒绝写入

### 新数据通知
- 新数据写入时通知所有已连接的客户端，传达新数据的类型和位置信息
- 通过心跳检测维持与已连接客户端的连接状态

### 记忆来源处理

#### 通道消息
使用统一的公共消息格式。memory 应该从 channel 获取附件，并按 key 存储二进制内容。

#### 大模型输出
思考内容存入思考记录。工具调用指令的 name 和 parameter 存入工具调用记录。大模型生成回复时由 nexus 发送 channel，用发送的返回值补充、替换消息内容后由 nexus 推送记忆存储。如果大模型生成文本，则构造文本类型的通道消息，否则按照大模型返回的数据类型构造相应消息类型的消息。

#### 工具输出
tool call 直接返回的内容存入工具调用结果记录。副产物（写入的文件等）不包含。记忆查询工具（nexus 内置 tool）的输出不送入记忆系统。
