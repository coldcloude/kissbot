# kissbot-memory-store 组件设计

## 概述
记忆存储模块，收集 nexus 和消息通道的全部原始消息（包括 channel 文本、思考内容、工具调用、工具结果），按统一格式持久化存储。填充记忆系统的原始数据层。

## 核心功能

1. **记忆写入**：接收 nexus 和消息通道推送的记忆记录，按统一格式持久化到文件系统
2. **记忆查询**：按时间范围查询记忆记录
3. **新数据通知**：新数据到达时通知所有已连接的记忆结构实现模块

## 内部模块

### 1. RecordManager - 记录管理器
- 管理多种类型记录的存储和读取
- 按日期自动创建目录和文件
- 支持追加记录、按时间范围查询

### 2. NotificationServer - 通知服务器
- 接受记忆结构实现模块的连接
- 维护已连接的客户端列表
- 新数据到达时通知所有已连接客户端
- 支持心跳检测、连接管理

### 3. API 服务器
- 提供记忆推送 API（接收 nexus/通道推送的记忆记录）
- 提供记忆查询 API

## 功能流程

### 记忆写入流程
收到推送请求 → RecordManager 解析 → 按时间组织文件目录 → 写入记录 → NotificationServer 广播通知。

### 记忆查询流程
收到查询请求 → RecordManager 使用 MemoryIndexer 定位 → 读取记录 → 返回。

## 记忆来源处理

### channel 消息
使用统一的公共消息格式。msg_type 为 text 时 content 为实际文本，否则 content 为全局唯一 key。
非text的场景中，memory 应该从 channel 获取附件，并按 key 存储二进制内容。

### 大模型输出
思考内容存入思考记录，不发 channel。工具调用指令的 name 和 parameter 存入工具调用记录。大模型生成回复时：如果为文本则构造 text 类型的 channel 消息，否则按照大模型返回的数据类型构造相应 msg_type 的消息。

### 工具输出
tool call 直接返回的内容存入工具调用结果记录。副产物（写入的文件等）不包含。记忆查询工具（nexus 内置 tool）的输出不送入记忆系统。
