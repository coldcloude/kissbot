# kissbot-memory-store 组件设计

## 概述

记忆存储服务是记忆系统中唯一写入原始记忆的组件。它接收 agent 推送的通道记录，按「agent + 记忆范围 + 日期」组织文件并持久化，提供按时间范围与最近条数的查询，并在写入完成后向订阅方广播「有新数据」的通知。

原始记录只追加、不删除、不修改。存储服务不解释记录内容，也不构建索引结构：索引结构由下游组件自行读取共享文件后建立。

## 核心功能

### Epic 1：记录写入与顺序

- **目标**：接收一批通道记录，按 agent、记忆范围与日期分文件落盘，并保证同一文件内的记录顺序与时间一致
- **依赖**：kissbot-memory（目录、路径与索引）、kissbot-api（记录类型）
- **用户故事**：
  - 作为一个外部系统（agent），我要推送一批通道记录，以把对话与智能体的行动持久化
  - 作为一个外部系统（agent），我要在记录时间早于文件已有记录时请求强制写入，以处理乱序到达的数据
  - 作为一个外部系统（agent），我要在写入返回时数据已经落盘，以确定写入是否成功
  - 作为一个管理员，我要让同一文件内的记录始终按时间有序，以使下游按顺序读取时不会错乱

### Epic 2：记录查询

- **目标**：按时间范围与最近条数查询指定 agent 与记忆范围的记录，返回按时间升序的结果
- **依赖**：kissbot-memory（内存索引）、Epic 1
- **用户故事**：
  - 作为一个外部系统（agent），我要按时间范围查询记录，以在上下文超长时回溯记忆
  - 作为一个外部系统（agent），我要取最近若干条记录，以在跨日期文件时也能拿到尾部内容
  - 作为一个外部系统（记忆管理界面），我要按范围读取记录，以展示或核对记忆内容

### Epic 3：新数据通知

- **目标**：写入完成后向已连接的下游组件广播新数据的位置，供其登记待处理
- **依赖**：Epic 1、kissbot-memory（通道身份）
- **用户故事**：
  - 作为一个外部系统（记忆结构实现），我要订阅新数据通知，以知道哪些记忆范围与通道有了变化
  - 作为一个外部系统（记忆结构实现），我要从通知中拿到位置而非内容，以按自己的水位从共享文件增量读取
  - 作为一个管理员，我要让通知只表示「有新数据」，以使下游可以在自己方便的时机处理

## 模块划分

- **记录写入器**：按 agent、记忆范围与日期分组，检查顺序、分配序号、追加或重写文件，并在写入后通知索引与订阅方
- **查询入口**：按时间与条数组织查询结果
- **索引配合**：写入后使查询索引感知新数据
- **通知服务**：独立的监听端点，维护已连接的订阅方，按通道广播位置信息
- **API 服务**：对外的写入与查询接口，统一响应格式与认证

## 功能流程

### 写入流程

```
收到一批记录 + 是否强制
  → 按 agent、记忆范围、日期分组（同文件的多通道记录合并为一次写）
  → 顺序检查：本批最早时间早于文件已有最晚时间时
      ├─ 未强制：整批拒绝，返回顺序错误（不写任何文件）
      └─ 强制：允许写入，交由写入器整文件重排
  → 按文件组织后写入：
      ├─ 顺序数据：按时间排序后逐条追加，序号递增
      └─ 乱序数据：读出全部旧记录与本批合并排序，重新编号后整文件重写
  → 刷新文件
  → 更新可查询的日期集合
  → 发布通知
  → 全部批次落盘后返回成功；任一批次失败则返回失败
```

### 查询流程

```
收到查询（时间范围 / 最近条数）
  → 按记忆范围与日期定位文件
  → 时间范围：按天切片后逐文件定位并读出，结果按天分组
  → 最近条数：从最近的日期向前逐文件取尾部，取满为止，再反转为时间升序
  → 返回记录（带文件内行号）
```

### 通知流程

```
记录写入并刷新完成
  → 把本批记录按通道分组
  → 每个通道一条通知（记忆范围、通道、该通道本批最后一条记录的位置）
  → 广播任务串行发送给所有已连接订阅方
      ├─ 发送失败：移除该订阅方
      └─ 未启动通知服务：通知丢弃
```

## 关键设计

### 只追加与整文件重写

顺序到达的数据直接追加；乱序到达且允许强制写入时，读出该文件全部记录与本批合并、按时间重新编号后整文件重写。这样无论数据以什么顺序到达，同一文件内的记录始终按时间有序，下游可以顺序读取。

### 序号是文件内物理位置

记录序号只在文件内唯一，表示记录在文件中的物理顺序。整文件重写会重新编号，因此序号不能跨文件比较，也不能作为全局标识；水位的比较依赖「时间 + 序号」这一组合。

### 顺序检查是尽力而为

顺序检查与实际写入不在同一临界区：检查通过后仍可能有其它写入插入。因此存储最终保证的是「文件内按时间有序」，而非「拒绝一切乱序到达」；顺序被拒只发生在检查时刻已经能判定乱序的场景。

### 落盘才算写入成功

写入请求返回时数据已写入文件、索引已感知新数据、通知已进入发送流程。写入失败会让整批返回失败。调用方因此可以把「写入返回成功」当作已落盘，而不会出现「返回成功但数据尚未写入」的窗口。

### 无去重

存储不按消息标识去重，重复推送会产生重复记录。去重是调用方的约定（例如发送后回显的消息不重复推送），不属于存储的职责。

### 通知只表达位置

通知携带记忆范围、通道与该通道本批最后一条记录的位置，不携带记录内容。订阅方按自己的水位从共享文件读取。这样通知与数据的传输解耦，订阅方也不必处理通知的内容格式。

### 通知是至多一次且易失的

通知没有确认、没有重投、没有持久化；订阅方断开期间的变更不会补发。订阅方需要在重连后自行按「全部记忆范围、全部通道」重新登记，以补齐断线期间的变化。因此通知只用于降低延迟，正确性由订阅方的水位与重扫保证。

### 同文件多通道按通道拆通知

同一 agent、同一记忆范围、同一天的所有通道共用一个文件，一批写入可能混合多个通道。通知因此按通道拆分逐条发出，避免下游漏掉同批中的其他通道。

### 索引由写入方驱动

存储写入后使索引感知新数据，读取路径因此始终能看到已落盘的记录；索引的更新策略见技术细节。
