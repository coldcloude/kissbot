# kissbot-memory-struct-abstract 组件设计

## 概述

摘要记忆实现组件，是记忆结构框架（kissbot-memory-struct）的一个实现模块，作为独立服务运行。组件用大模型把原始记忆划分为事件：一个事件的记忆单独摘抄一份完整记录并生成摘要；新记忆数据经判定归档到事件，必要时自顶向下分层归并；新消息到达时先定位所属事件，取事件的摘要或原文作为上下文。

组件只负责「记忆的事件化组织与定位」，不改变原始记忆的存储，也不消费定位结果——定位结果如何进入 nexus 的上下文由后续独立实现（输入处理器或原生工具）承担。

## 核心功能

### Epic 1：新数据订阅与归档触发
- **目标**：订阅记忆存储的新数据通知，按通道消息的发送者身份与时间判定归档时机，形成待归档批次
- **依赖**：kissbot-memory-store（新数据通知服务）、kissbot-memory（原始记录的读取与索引）
- **用户故事**：
  - 作为一个外部系统（记忆存储模块），我要在写入新记录后向已连接的摘要记忆广播通知，以使摘要记忆及时获得待归档数据
  - 作为一个外部系统（记忆存储模块），我要在通道消息的通知中给出时间、agent、角色与发送者身份，以使摘要记忆据此判定归档时机
  - 作为一个管理员，我要配置归档触发的超时时间，以使尾部消息在没有后续消息时也能归档

### Epic 2：事件归档与分层归并
- **目标**：把待归档批次交大模型判定归属，并入当前事件、归并到已有事件或新建事件节点，形成多层事件结构
- **依赖**：Epic 1（待归档批次）、kissbot-llm（模型调用）
- **用户故事**：
  - 作为一个管理员，我要新记忆数据自动归档到合适的事件，以使记忆按事件组织而无需人工整理
  - 作为一个管理员，我要新事件自顶向下归并到已有事件之下，以使事件形成多层结构
  - 作为一个调用方，我要事件模式下的记忆整体归为一个事件，以使按事件隔离的上下文不被再次切分

### Epic 3：事件内容与摘要维护
- **目标**：为每个事件保存归属它的原始记录副本与大模型摘要，内容变化后重算摘要并级联更新祖先摘要
- **依赖**：Epic 2（事件与层级）、kissbot-llm（模型调用）
- **用户故事**：
  - 作为一个调用方，我要事件自包含原文副本与摘要，以使事件不受原始记录流后续变化的影响
  - 作为一个调用方，我要父事件摘要涵盖其子事件内容，以使大事件摘要完整反映其内容

### Epic 4：事件定位与上下文供给
- **目标**：根据新消息定位所属事件，返回事件摘要与原文副本作为上下文
- **依赖**：Epic 2、Epic 3（事件内容与层级）、kissbot-llm（模型调用）
- **用户故事**：
  - 作为一个调用方，我要传入 agent、角色与新消息并取回所属事件的摘要或原文，以作为后续模型调用的上下文
  - 作为一个调用方，我要定位优先命中当前事件，以减少定位开销
  - 作为一个调用方，我要在定位未命中时得到空结果，以识别话题切换

### Epic 5：事件查询与管理
- **目标**：提供事件树、事件详情与处理状态的查询，以及手动触发与重建能力
- **依赖**：Epic 2、Epic 3
- **用户故事**：
  - 作为一个管理员，我要查询某作用域的事件树与事件详情，以核对记忆组织是否正确
  - 作为一个管理员，我要手动触发或重建某作用域的归档，以处理通知缺失或导入历史记录
  - 作为一个外部系统（记忆管理界面），我要读取事件与摘要，以在界面上展示与维护

## 模块划分

- **通知订阅**：连接记忆存储的通知服务，维护长连接与重连
- **触发判定**：按作用域维护已处理水位，按发送者身份与超时判定归档时机
- **记录读取**：按时间范围从共享记忆文件读取四类原始记录
- **事件树管理**：事件节点、层级与当前事件指针的读写和持久化
- **归档器**：第 1 轮归属判定、分层下探落位、批内多事件切分
- **摘要器**：事件摘要生成与祖先摘要级联重算
- **定位器**：按新消息匹配事件并装配上下文
- **API 服务**：对外查询、定位与管理接口
- **配置**：组件配置读取（模型 provider、超时、服务地址、数据目录）
- **模型接入**：复用 LLM 基础库完成模型调用与会话上下文管理

## 功能流程

### Epic 1 归档触发流程
记忆存储写入新记录 → 广播通知 → 摘要记忆按作用域登记通知信息。
通道消息通知：未归档范围内出现本人消息、且其后出现非本人消息时判定为归档时刻，归档范围截止到最后一条本人消息（含）；超过超时时间无新消息时，归档范围截止到最后一条消息（含）。
思考、工具调用、工具结果的通知不触发归档。
归档范围确定后推进水位，交给归档流程；未纳入的记录留待下次触发。

### Epic 2 事件归档流程
取待归档批次 → 事件模式的作用域：直接并入该作用域唯一的顶层事件。
角色模式的作用域：
1. 第 1 轮——以批次内容与当前事件摘要判定：并入当前事件，或判为新事件（批次跨越多个事件时同时给出切分点）。
2. 判为新事件则进入分层归并——自顶层起逐层给出当层全部事件摘要：当层新开事件，则在该层新建节点；并入某事件，则该事件为叶子时内容并入，非叶子时下潜到其子层继续判定。
3. 落位后追加原文副本 → 重算该事件摘要 → 级联重算祖先摘要 → 更新当前事件指针。

### Epic 3 摘要生成流程
事件内容变化 → 汇总该事件的直接记录与子事件摘要 → 模型生成摘要 → 更新节点 → 自底向上重算受影响的祖先摘要。

### Epic 4 事件定位流程
新消息到达 → 先与当前事件比对 → 命中即装配上下文返回。
未命中则自顶层逐层下探 → 命中即装配上下文返回；均未命中返回空。
上下文装配：命中事件的摘要（命中父事件时附其子事件摘要），以及预算内的原文副本。

### Epic 5 查询与管理流程
查询请求 → 事件树管理按作用域读取树与事件数据 → 返回。
重建请求 → 复位该作用域水位 → 按共享记忆文件重新构建事件树与摘要。

## 关键设计

### 事件树组织
事件以 (agent, 角色) 为作用域组织成一棵树，跨年份持续累积；大事件可以包含子事件。每个事件保存归属它的原始记录副本与大模型摘要，内容自包含。父事件摘要由自身直接记录与子事件摘要合成。

### 两种记忆来源
- **角色模式**：作用域内的记录经模型判定切分为事件，可多层归并。
- **事件模式**：作用域整体对应一个顶层叶子事件，内部不再划分，也不参与分层归并。

### 当前事件优先
每个作用域维护一个当前事件指针，指向最近被并入内容的事件。归档的第 1 轮判定与事件定位都先与该事件比对，未命中才扩大到更大范围，以落实「优先选择当前事件」并控制调用开销。

### 归档以通道消息为准
只有通道消息通知触发归档；思考与工具调用、工具结果的通知不触发，但它们的记录作为事件内容随批次一并归档，使事件完整保留推理与行动轨迹。

### 触发边界落在本人消息
出现非本人消息时，说明上一轮对话已经结束，归档范围因此截止到最后一条本人消息；长时间没有新消息则由超时触发收尾。两种触发都只向前推进水位，不重复归档已处理记录。

### 分级候选控制上下文规模
第 1 轮只给当前事件摘要，第 2 轮起才逐层给出当层全部事件摘要，避免一次把全部事件摘要送入模型。

### 模型接入
模型调用与会话上下文复用 LLM 基础库，会话按事件作用域隔离；组件自身持有 provider 配置，不读取 agent 的配置。

### 关联事件（预留）
事件之间的关联关系、关系描述，以及关联事件摘要纳入上下文，留待后续实现；第 1 轮的候选集合已按可扩展的列表形式组织。

### 与 nexus 的边界
组件提供归档与定位能力，不接入 nexus 的 agentic loop。定位结果的消费方（输入处理器或原生工具）以及 agentic loop 内的记忆搜索工具均为后续独立实现。
