# kissbot-memory 组件设计

## 概述

kissbot-memory 是记忆系统的基础库，以程序库形式被记忆存储、自我认知与摘要记忆三个服务以及 agent 使用。它定义记忆的目录布局、记忆范围的命名规则、通道记录的形态与文件路径规则，并提供目录管理与查询能力，使这些组件共享同一份文件系统数据而不各自发明目录结构。

记录本身只追加、不修改，索引结构由上层组件建立；本组件只负责「数据放在哪里、怎么读得快」。

## 核心功能

### Epic 1：目录与 agent 管理

- **目标**：管理记忆根目录与各 agent 的子目录，区分不同组件的数据区，并标识哪些目录对应已创建的 agent
- **依赖**：配置（记忆根目录）
- **用户故事**：
  - 作为一个外部系统（记忆存储服务），我要为某个 agent 确保记录目录存在，以让写入有确定位置
  - 作为一个外部系统（自我认知服务），我要在创建 agent 时写入存在标记，以让系统能够列举已创建的 agent
  - 作为一个外部系统（记忆结构实现），我要获得自己的数据目录，以在不干扰其他组件的前提下保存索引数据
  - 作为一个管理员，我要查询所有已创建的 agent，以了解系统中存在哪些 agent

### Epic 2：记忆范围与路径构造

- **目标**：以「角色 + 可选事件」表达记忆范围，由本组件统一构造目录与文件名，按年与日期分文件
- **依赖**：Epic 1（目录与 agent 管理）
- **用户故事**：
  - 作为一个外部系统（记忆存储服务），我要传入 agent、记忆范围与时间，以得到该记录应写入的文件位置
  - 作为一个外部系统（agent），我要用角色或「角色 + 事件」表达记忆范围，以使用角色记忆或事件记忆而不关心文件名规则
  - 作为一个管理员，我要让两种记忆模式共用同一套存储规则，以在切换模式时不迁移数据

### Epic 3：记录模型

- **目标**：定义通道记录及其内容的形态，使一条记录能完整表达一次消息收发及其附带的思考与工具内容
- **依赖**：Epic 2（记忆范围与路径构造）
- **用户故事**：
  - 作为一个外部系统（记忆存储服务），我要按统一形态保存来自通道的消息，以让所有通道的记录可被统一读取
  - 作为一个外部系统（摘要记忆服务），我要读取记录中的思考与工具内容，以在摘要中保留推理与行动轨迹
  - 作为一个外部系统（摘要记忆服务），我要在记录上附加自己的归属信息，以在归档时直接定位而不重新判定

### Epic 4：索引与查询

- **目标**：为记录文件维护查询索引，支持按时间范围、按位置与按条数快速读取
- **依赖**：Epic 2、Epic 3
- **用户故事**：
  - 作为一个外部系统（记忆存储服务），我要按时间范围查询记录，以响应调用方的记忆回溯
  - 作为一个外部系统（记忆存储服务），我要取最近若干条记录，以在跨日期文件时也能返回尾部内容
  - 作为一个外部系统（摘要记忆服务），我要按文件位置读取记录之后的内容，以增量跟进而不用重读全量
  - 作为一个外部系统（写入方），我要在写入后让索引感知新数据，以使后续查询能读到新记录

## 模块划分

- **目录管理**：根目录与各 agent 子目录的创建与识别，agent 存在标记，已创建 agent 的列举
- **路径构造**：按 agent、记忆范围与时间构造记录文件路径，并按需创建目录
- **记录模型**：通道记录、记录内容（文本、复合、附件、系统通知、思考、工具调用、工具结果）、记录元信息的定义
- **索引**：按文件维护时间与位置索引，提供时间范围、指定位置前后与首尾若干条的查询
- **跨文件定位**：记录哪些日期存在数据，用于跨日期的尾部读取

## 功能流程

### 目录使用流程

```
服务启动
  → 读取记忆根目录配置并取得目录管理器
  → 创建组件需要的数据目录
写入前
  → 按 agent 确保目录存在（需要标记已创建 agent 时同时写存在标记）
查询已创建 agent
  → 扫描根目录下带存在标记的子目录
```

### 写入路径构造流程

```
写入方给出 agent、记忆范围、记录时间
  → 由角色与可选事件拼出记忆范围名
  → 按记录时间取年份与日期
  → 拼出该年份与记忆范围对应的目录、该日期对应的文件
  → 确保目录存在
  → 返回文件位置
```

### 查询流程

```
查询方给出 agent、记忆范围与查询条件（时间范围 / 位置 / 条数）
  → 按时间与位置条件定位记录
  → 返回记录（带文件内位置）
跨日期取尾部时：从最近的日期开始逐日向前取，取满即停
```

## 关键设计

### 记忆只追加

记录一旦写入即不修改，因此存储层只需支持追加与重写两种写入方式。索引建立在这份只追加的数据之上，可以随时重建而不影响原始记忆。

### 记忆范围在构造文件名时才拼接

调用方以「角色 + 可选事件」表达范围，拼接规则只存在于本组件。这样角色名与事件标识的字符规则、磁盘目录的命名方式可以独立演进，调用方不需要知道文件长什么样。

### 角色与事件在磁盘上并列

同一 agent 下，角色模式与各事件模式是并列的记忆范围，角色模式不是事件模式的父目录。两种模式只是范围名的构造规则不同，存储与索引完全共用。

### 单文件承载多通道

同一 agent、同一记忆范围、同一天的所有通道记录共用一个文件，记录自身携带通道身份。这样写入只需按时间分片，读取时再按通道过滤；代价是文件内混合多个通道，需要按身份字段区分。

### 索引随写入更新

本组件不监听文件变化。写入方在写入完成后使索引感知新数据，索引在下一次读取时反映最新内容；索引的具体更新策略见技术细节。

### 存在标记决定 agent 是否可见

agent 目录只有在带有存在标记时才被列举出来，而标记由创建 agent 的服务写入。因此「目录存在」与「agent 已创建」是两件事：单独的记录写入不会让某个标识出现在 agent 列表中。

### 索引不持久化

索引在进程内维护、不落盘，规模随数据量增长。这符合记忆只增不减的使用方式，也意味着每次启动都要重新建立索引。

### 看到新记录的前提

索引与文件读取在同一进程内共享，读取方能看到刚写入的记录，前提是写入方在提交后完成了写入。这一点是使用本组件的约定，而非组件内部隐含保证的。
