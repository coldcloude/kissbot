# kissbot-memory 组件设计

## 概述
记忆基础模块，定义记忆系统的文件存储目录结构、记录类型和持久化格式，提供目录管理、文件路径构造和内存索引能力。作为程序库供其他记忆模块（记忆存储模块、记忆结构模块、自我认知模块）使用。

记忆系统支持两种组织模式——角色记忆和事件记忆。两种模式共用同一套存储和索引机制，区别仅在于目录名的构造方式。推送方和查询方拼接角色标识或事件标识作为后缀传给记忆基础模块，由本模块构造完整路径。

## 核心功能

### Epic 1：文件系统目录管理
- **目标**：管理记忆系统根目录和各 agent 的子目录结构，自动创建目录结构和标识文件
- **依赖**：无
- **用户故事**：
  - 作为一个外部系统（系统启动程序），我要初始化目录管理器，以建立记忆系统的根目录结构
  - 作为一个外部系统（记忆存储模块），我要为指定 agent 创建文件目录，以确保持久化路径可用
  - 作为一个外部系统（记忆存储模块），我要在创建 agent 目录时写入唯一标识文件，以标记该目录属于某个有效 agent
  - 作为一个管理员，我要查询所有有效 agent 的目录列表，以获取系统中已注册的 agent 清单

### Epic 2：记忆记录类型定义
- **目标**：定义标准化记忆记录类型，覆盖通道消息、思考内容、工具调用和工具结果四种记录格式
- **依赖**：无
- **用户故事**：
  - 作为一个外部系统（记忆存储模块），我要使用标准的通道消息记录类型存储来自消息通道的消息，以统一记忆数据格式
  - 作为一个外部系统（记忆存储模块），我要使用思考记录类型存储智能体的思考过程，以保留 LLM 推理轨迹
  - 作为一个外部系统（记忆存储模块），我要使用工具调用记录类型存储工具调用指令（名称和参数），以记录智能体的行动决策
  - 作为一个外部系统（记忆存储模块），我要使用工具结果记录类型存储工具执行结果，以记录行动后的反馈

### Epic 3：文件路径构造
- **目标**：接收 agent 标识、年份和后缀返回完整存储路径，支持自动创建目录
- **依赖**：Epic 1（目录管理）
- **用户故事**：
  - 作为一个外部系统（记忆存储模块），我要传入 agent 标识、年份和后缀获取完整的文件系统路径，以确定文件存储位置并在同一目录下区分各类数据

### Epic 4：内存索引与查询
- **目标**：为记录文件在内存中维护懒更新索引，提供按时间范围快速查询四种记录类型的能力
- **依赖**：Epic 1（目录管理）、Epic 2（记录类型定义）、Epic 3（路径构造）
- **用户故事**：
  - 作为一个外部系统（记忆存储模块），我要按时间范围分别查询通道消息、思考、工具调用、工具结果四种记录类型，以获取某时间段内的所有记忆数据

### Epic 5：记录文件操作框架
- **目标**：提供通用的文件读写框架，包含文件追加、排序写入、变更回调等能力
- **依赖**：Epic 1（目录管理）、Epic 2（记录类型定义）
- **用户故事**：
  - 作为一个外部系统（记忆存储模块），我要追加记录到记录文件，以保证同一文件内的记录有序、查询结果保持时效
  - 作为一个外部系统（记忆存储模块），我要在写入的记录时间顺序异常时请求强制写入，以处理非顺序到达的数据

## 内部模块

### 1. 目录管理器
- 管理记忆系统根目录，创建 agent 目录及其子目录
- 通过检查 agent 标识文件判断目录有效性
- 提供全量 agent 查询

### 2. 记忆索引器
- 在内存中为四种记录类型分别维护懒更新索引，提供按时间范围快速查询
- 支持增量追加（读取文件尾部新记录）和全量重建（重新读取整个文件）
- 通过脏标记延迟更新索引

### 3. 路径构造器
- 提供路径构造接口：接收 agent 标识、年份和后缀，返回完整路径
- 后缀由调用方拼接，本模块不做解析
- 确保目标目录存在（自动创建）

### 4. 记录类型定义模块
- 定义四种标准记录类型：通道消息记录、思考记录、工具调用记录、工具结果记录
- 定义记录的通用接口（序列化、序号管理、时间比较）
- 定义文件名生成规则和各类型专用的文件名解析规则

## 功能流程

### Epic 1 目录管理流程
系统启动时加载配置 → 目录管理器获取或初始化根目录 → 按需创建 agent 目录 → 写入或校验 agent 标识文件 → 扫描根目录返回 agent 清单。

### Epic 2 记录类型使用流程
消息产生后 → 调用方根据消息类型选择对应记录类型 → 填充记录字段 → 序列化为文本行 → 写入记录文件。

### Epic 3 路径构造流程
调用方传入（agent 标识、年份、后缀）→ 路径构造器接收参数 → 拼接为完整文件系统路径 → 确保路径对应目录存在 → 返回路径给调用方。

### Epic 4 索引维护与查询流程
首次查询时记忆索引器读取所有文件建立索引 → 收到脏标记后下次查询前增量读取新行追加索引（或全量重建）→ 查询请求分段 → 反向读取每一天的记录 → 汇总排序后返回。

### Epic 5 记录文件操作流程
记录管理器接收写入请求 → 按记录类型和日期分组 → 获取文件级锁 → 读取文件尾获取当前最大顺序编号 → 分配新编号 → 按时间排序后追加到记录文件 → 触发回调标记索引脏 → 返回。

## 关键设计

### 目录结构约定
- 记忆系统根目录下按 agent 建立子目录，agent 目录通过唯一标识文件标记有效性
- 记录文件路径由 agent 标识、年份和调用方后缀拼接而成，后缀由调用方拼接，本模块不做解析

### 路径与文件名约定
- 路径构造器在目标目录不存在时自动创建目录
- 不同类型的记录使用不同的文件名前缀，在同一目录下区分通道消息、思考、工具调用、工具结果

### 记录写入规则
- 追加记录时分配递增的顺序编号，保证同一文件内记录有序；写入后触发回调通知索引模块标记脏数据
- 记录时间顺序异常时支持强制写入：全量读取后重新排序再写回，并全量重建索引

### 索引懒更新
- 内存中为四种记录类型分别维护懒更新索引，文件修改时标记脏，下次查询前按需增量追加或全量重建
