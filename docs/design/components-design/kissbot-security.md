# kissbot-security 组件设计

## 概述

安全基础库，为各组件提供统一的认证能力。当前只做认证、不做授权：校验请求方是否持有预配置的 API key，不区分其可执行的操作。HTTP 请求与 WebSocket 握手共用同一套校验逻辑。

## 核心功能

### Epic 1：请求认证

- **目标**：提供可复用的 API key 校验能力，供 HTTP 中间件与 WebSocket 握手过滤共同使用
- **依赖**：kissbot-config（读取公共配置中的密钥）
- **用户故事**：
  - 作为一个外部系统（组件进程），我要用统一的校验方式保护自己的服务，以拒绝未持有密钥的请求
  - 作为一个外部系统（组件进程），我要在校验失败时得到明确的错误，以返回恰当的响应
  - 作为一个外部系统（组件进程），我要按需替换校验实现，以接入不同的密钥来源

### Epic 2：HTTP 与 WebSocket 接入

- **目标**：把校验能力接入两种通信方式：HTTP 请求在中间件层拦截，WebSocket 在握手阶段拦截
- **依赖**：Epic 1（请求认证）
- **用户故事**：
  - 作为一个外部系统（组件进程），我要把认证挂到 HTTP 路由上，以在业务处理前统一拦截
  - 作为一个外部系统（组件进程），我要在 WebSocket 握手时校验密钥，以拒绝未认证的连接
  - 作为一个客户端，我要在请求与握手时携带密钥，以完成认证

### Epic 3：安全配置

- **目标**：从公共配置中读取两类密钥：组件之间互调的通用密钥，以及管理端专用的密钥
- **依赖**：kissbot-config
- **用户故事**：
  - 作为一个管理员，我要在公共配置中设置通用密钥，以控制组件之间的互调访问
  - 作为一个管理员，我要设置管理端密钥，以把管理操作与普通接口访问分开
  - 作为一个外部系统（管理界面），我要使用管理端密钥访问管理 API，以获得更高的访问能力

## 模块划分

- **认证类型**：密钥请求头名称、认证失败的错误类型等公共定义
- **校验器**：校验接口与简单的字符串比对实现，调用方也可自行实现
- **HTTP 接入**：以中间件形式挂载到路由上，校验通过后交给业务处理
- **WebSocket 接入**：握手阶段的过滤器，校验失败时拒绝建立连接
- **安全配置**：从公共配置读取通用密钥与管理端密钥，提供全局访问

## 功能流程

```
HTTP 请求到达
  → 从请求头提取密钥
      ├─ 缺失或与配置不一致：返回未认证响应，不进入业务处理
      └─ 一致：交给业务处理

WebSocket 握手请求到达
  → 从握手请求头提取密钥并按同一校验器校验
      ├─ 失败：拒绝连接
      └─ 通过：建立连接
```

## 关键设计

### 只认证不授权

校验只回答「请求方是否持有密钥」，不区分管理员与普通用户的能力差异。权限划分由各组件的接口设计承担：管理端接口使用管理端密钥，普通接口使用通用密钥，二者用不同密钥即形成隔离。

### 单一密钥

每个密钥只有一份预配置值，不支持多用户、多密钥或动态签发。密钥通过公共配置下发，所有组件读取同一份配置即可互认。

### 两种通信方式共用校验

HTTP 与 WebSocket 使用同一个校验接口与同一份密钥，因此不会出现「HTTP 被保护而 WebSocket 未保护」的缺口。WebSocket 只在握手阶段校验一次，连接建立后不重复校验。

### 校验实现可替换

校验接口独立于具体实现，默认实现是字符串比对。需要更复杂的密钥来源时，组件可以提供自己的校验实现而无需改动接入层。
