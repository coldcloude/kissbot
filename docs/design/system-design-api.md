# system-design-api 组件设计

## 概述
API 定义模块，定义各模块间通信的标准数据结构和统一的 API 响应格式。是模块间数据交换的契约层。

## 核心功能

1. **标准数据类型定义**：定义各模块间通信所需的基础类型（字符串类型、映射类型、集合类型等）
2. **API 响应格式**：定义统一的 API 响应结构
3. **模块专属类型定义**：为每个模块定义其专用的请求/响应类型

## 内部模块

### 1. 网络地址配置模块（config）
- 定义 API 网络地址配置：memory-store、memory-ego 的访问地址
- 从公共配置的 `api` 段读取，提供全局访问
- 各组件通过此模块统一获取其他服务的访问地址

### 2. kinds 模块
基础类型接口定义：字符串类型、映射类型、集合类型的抽象。

### 3. common 模块
通用 API 类型：统一的 API 响应结构。

### 4. ego 模块
自我认知模块相关的所有 API 类型：Agent 管理、个体识别信息、角色设定等。

### 5. store 模块
记忆存储模块相关的所有 API 类型：记忆推送、记忆查询等。

### 6. channel 模块
消息通道模块相关的 API 类型。

## 设计原则

### 数据类型一致性
保证各模块在内部使用和对外通信时使用一致的数据类型，避免类型转换错误。

### 直接序列化
并发容器类型可直接序列化和反序列化，无需转换。
