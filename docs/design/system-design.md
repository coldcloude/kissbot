# 系统设计文档

## 概述
本项目实现一个AI智能体及其记忆系统、消息系统等附属组件。

## 一、组件体系

### 1. Agent
智能体组件，由 Nexus（LLM 通信枢纽）和 Station（Tool 执行主机）两个内部模块组成，模块职责与内部结构详见 [system-design-agent](system-design-agent.md)。

Agent 程序可在启动时选择开启的部分（仅 nexus / 仅 station / 同时开启），同一系统内可运行多个 agent 实例，各实例可开启不同的部分、对接不同的 LLM 模型或服务于不同的场景。

Agent 除了根据外界信息给出回应外，还可以主动获取信息并据此行动。可以为 agent 设计自主行动的目标，agent 据此执行信息收集、信息反馈、自动工具调用等。

> 注：记忆查询属于 nexus 内置工具，不经由 station 执行。

### 2. 消息通道（Channel）
连接外部系统的桥梁。定义统一的 Messenger 接口（通讯应用接入标准，包含消息收发等功能），提供通道管理器作为核心协调层。具体的通讯应用接入由通道实现组件完成。

**通道实现组件**：实现 Messenger 接口，负责连接具体的外部系统（如 Web 页面、QQ 等），实现用户管理、群组管理、消息收发、附件管理等功能。通道实现可以是仅作为对接层接入现有消息工具（如 QQ 机器人），也可以是包含消息工具和对接层的完整实现（如 Web 前后端）。

### 3. 记忆系统
所有 nexus 共用同一套记忆系统，设计为在保存全部原始记忆数据的基础上，对接各种记忆提取、归纳、索引的结构，以便在保证记忆完整性的同时，降低记忆召回的难度。

**记忆基础组件**：定义记忆文件系统的目录结构，提供目录管理和索引查询框架。提供路径构造接口——推送方和查询方传入 `(agent-id, year, suffix)`，由本组件拼接完整路径。suffix 由调用方按记忆模式拼接，本组件不做解析。支持两种记忆组织模式：
- 角色记忆：suffix 为角色标识，按角色组织所有历史记录
- 事件记忆：suffix 为角色标识加事件标识，按事件隔离上下文

**记忆存储组件**：收集 nexus 推送的全部原始消息（包括 channel 消息、思考内容、工具调用等类型）并持久化存储，提供记忆推送和查询 API。有新数据时通知各已连接的记忆结构组件。其中 channel 消息使用统一的公共消息格式。

**记忆结构框架**：定义记忆结构构建的标准接口。具体实现由独立的记忆结构实现组件完成。

**记忆结构实现组件**：读取记忆存储组件中的原始记忆记录，构建特定索引结构（如摘要索引、最近记忆索引等），提供记忆搜索工具供 nexus 通过 tool call 调用。

### 4. 自我认知组件（Memory-Ego）
管理和获取 agent 的自我认知设定。提供 agent 元数据、个体识别信息、角色设定等数据的存储和查询能力。

### 5. API 定义
定义各组件间通信的标准数据结构和统一的响应格式，是组件间数据交换的契约层。内部模块与设计原则详见 [system-design-api](system-design-api.md)。

### 6. 安全组件
多种安全模块统一放在安全组件中，当前模块如下：
- **认证模块**：为所有模块提供统一的认证能力。
- **配置模块**：定义 `SecurityConfig`（api_key、admin_api_key），从公共配置中读取安全相关的配置项。

### 7. 公共配置组件
集中管理所有组件的配置信息。各组件不再各自定义配置文件和加载方式，改为从一份公共 JSON 配置文件中提取各自需要的部分。

**公共配置组件**：加载 JSON 配置文件（通过 `KISSBOT_CONFIG` 环境变量指定路径，默认 `./config.json`），提供层级化的配置访问接口 `get_section(path)`。组件间通过点号路径解耦。

**网络地址配置**：定义各组件访问其他服务的 URL（memory_store_url、memory_ego_url），由 `ApiConfig` 封装（详见 [system-design-api](system-design-api.md)），各组件统一从该配置中读取外部服务地址。

**安全配置**：所有 API key 统一归入 `security` 配置段，由 `kissbot-security` 的 `SecurityConfig` 封装。各组件通过 `SecurityConfig::get()` 获取认证所需的 key。

### 8. 管理界面
提供 Web 界面的管理工具集，包括：
- **智能体配置界面**：配置 nexus 使用的 LLM API、连接的 station、记忆模式，以及各类组件地址
- **记忆管理界面**：查看和管理记忆存储文件，配置记忆推送

## 二、组件间通信

### 通信总览

| 发送方 | 接收方 | 通信内容（方向） | 通信时机 |
|--------|--------|-------------------|----------|
| nexus | 消息通道 | 绑定请求（→）、下行消息/回复/思考（→）、附件下载请求（→）、心跳（↔） | nexus 启动时绑定；有消息回复时；需要附件时 |
| 消息通道 | nexus | 上行消息/用户消息（→）、群组变化通知（→）、附件数据（→）、心跳（↔） | 外部消息到达时；群组变化时；nexus 请求附件时 |
| nexus | station | tool call 请求（→）、tool result 响应（←） | agentic loop 内需要时 |
| nexus | memory-store | 推送记忆记录（→） | 每条消息产生时（含收发的通道消息） |
| nexus | memory-struct-* | 记忆查询请求（→）、查询结果（←） | agentic loop 内 LLM 调用记忆搜索工具时 |
| nexus | memory-ego | 读取自我认知设定（→）、返回设定（←） | nexus 启动时；上下文重置时 |
| memory-store | memory-struct-* | 新数据通知（→） | 新数据到达时 |
| memory-store / memory-struct-* | 文件系统 | 共享读写记忆文件（↔） | 持续 |
| 通道前端（浏览器） | 通道后端 | 消息收发、群组管理、附件操作（↔） | 用户操作时 |
| 通道后端 | 通道前端（浏览器） | 实时推送新消息（→） | 持续 |
| 智能体配置界面 | nexus | 读取/更新配置（↔） | 用户操作时 |
| 智能体配置界面 | station | 读取/更新配置（↔） | 用户操作时 |
| 记忆管理界面 | memory-store | 查看管理记忆（↔） | 用户操作时 |
| 记忆管理界面 | memory-struct-* | 查看管理（↔） | 用户操作时 |
| 记忆管理界面 | memory-ego | 查看管理（↔） | 用户操作时 |

## 三、关键设计

### 统一的公共消息格式
channel 和 memory 使用统一的公共消息格式。msg_type 为 text 时 content 为实际文本；multi 时 content 为 JSON 列表，每个元素包含 msg_type 和 content 两个字段；其他类型 content 为全局唯一 key——channel 通过 key 关联附件，memory 按 key 存储二进制内容。

### nexus 与记忆系统的交互
nexus 与记忆系统的交互区分两种模式：
  - agentic loop 外：直接调用 API 读取自我认知设定、推送记忆到存储组件
  - agentic loop 内：由 LLM 通过 nexus 内置 tool 从记忆结构组件查询记忆（不记入记忆）

### 会话与绑定
一个 nexus 可同时管理多个会话。nexus 为每个绑定的 channel 配置 agent_id、role_name、mode，并将所有绑定项的信息去重，每个 agent_id+role_name+mode 组合为一个会话；各会话拥有独立的 LLM 上下文、记忆读取范围与模式状态，消息按来源 channel 对应的绑定配置路由到对应会话。每个会话从其绑定的多个 channel 中选定一个作为回复 channel，回复消息通过该 channel 发送。

### Agent 的自我认知机制
每个 agent 具有双重自我认知设定：
- **客观设定**：每个 agent 一份，包括身份标识（个体名称、描述）、个体识别信息（个体名称、和agent的关系、和其他个体的关系、关联的消息通道身份）、禁止事项和自主运行目标
- **角色设定**：每个 agent 可有多份，以角色名称为标识，包括角色描述、禁止事项、自主运行目标、和其他角色的关系、其他角色关联的个体信息

nexus 在启动时或上下文重置时读取自我认知信息，构建到系统消息中，使 agent 知道自己是谁、面对什么个体、扮演什么角色。

### 通道实现组件的消息存储
- 当通道实现仅作为对接层时，不存储历史消息，所有历史消息由记忆存储组件保存
- 当通道实现为包含消息工具的完整实现时，应有消息和附件存储等功能
