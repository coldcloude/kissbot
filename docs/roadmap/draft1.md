继续实现摘要记忆：
1、agent的修改：input_processor已经整体重构了，因此去掉absttract_input_processor，改为一个abstract_memory_pipeline.sh，实现使用摘要记忆的完整pipeline。其中接入channel部分改为一个pipeline维护一个ChannelBatchProducer的DashMap，key是ChannelKey，来自不同channel的消息有自己的合并队列，以保证不同channel的消息互不干扰，实现IncomingMessageProcessor和IncomingMessageBatchProcessor以实现这一目标。同时，要增加Producer的退出机制。AgentPipeline在当前的incoming_message和reset_system_prompt外，增加一个接口函数，用于接收channel不再绑定本session的消息，此时清理该channel的所有messenger+user对应的ChannelBatchProducer。channel在change key时，对旧的pipeline调用这个接口。可以在nexus中将 解绑agent + prune session / pipeline + 新建session 合成一个便利函数。
2、记忆结构修改。记忆结构中增加一个可选的meta字段，各组建可以用meta字段存储一些额外的信息。摘要记忆场景下，可以在meta中增加一个摘要记忆信息struct字段，其中可以包括这条记忆所属case的名称，当摘要记忆组件读到有这个信息的记忆时，直接使用该case名称定位，不再走locate流程。该字段由locate的调用方填入记忆中。因此nexus也要作一个重大改动。将ChannelRequest的构造提取为根据incoming构造和根据outgoing构造的两个纯函数，从nexus中去掉发送记忆request的动作，改为在pipeline中执行。在DefaultAgenticLoopPipelineWithMemory中，可以在incoming_message中处理。send_outgoing直接挪到pipelines里。在摘要记忆的pipeline里，延后到locate之后再处理。这样修改后，locate也可以简化，不再需要去重，message到达时必定还没有写入记忆。并且在摘要记忆的pipeline里，model_response可以直接根据当前触发时的case，也写入meta字段，不用在做locate。
