# Agent pipeline 机制

> 说明 pipeline 的装配、路由、会话、合批、执行循环、命令与记忆写入的实现约定。设计意图见 `docs/design/components-design/kissbot-agent-nexus.md`。

## 一、装配与输入路由

- 顶层 pipeline 配置给出「agent → 角色 → pipeline 实现名」。启动时按 agent 与角色排序遍历，为每个组合装配一条 pipeline；实现名未知或装配失败时记日志并跳过该条。
- pipeline 的身份是「agent + 角色」。配置里的角色为空串表示该 agent 的默认角色；没有任何角色条目的 agent 不会装配 pipeline。
- 每条 pipeline 的输入身份列表来自该 agent/角色合并后的配置。合并规则是「角色列表整体替换 agent 列表」：角色未配置时为空，不继承 agent 级。
- 绑定输入身份时先登记「输入身份 → pipeline」路由：一个身份只能绑定一条 pipeline，先绑定者生效，后到者记错误并跳过；同一条 pipeline 重复绑定同一身份静默忽略。
- 登记路由后取该 channel 的运行态：channel 不存在或未启用时只保留路由、不建立连接；已连接时立即向通道服务端绑定该身份。
- channel 运行态首次创建时启动连接循环，同一 channel 只有一个循环。连接成功后绑定该 channel 上的全部输入身份；断线回调后按配置的重连间隔重连，重连成功重新绑定。
- 运行期由管理接口增删 pipeline 或输入身份，走同一套绑定/解绑逻辑。

## 二、会话标识与配置

| pipeline | 角色模式 | 事件模式 |
|----------|----------|----------|
| 无记忆对话 | `default-{agent}-{role}` | `default-{agent}-{role}-event-{event}` |
| 带记忆对话 | `default-memory-{agent}-{role}-topic-{uuid}` | `default-memory-{agent}-{role}-event-{event}` |
| 摘要记忆对话 | 每个 case：`memory-summary-{agent}-{role}-{case_name}`（`/` 编码为 `.`、方括号换成下划线）；基准会话：`...-none` | 同左（case 会话与事件无关） |

- 建立会话时先构造对象并从本地缓存全量回读，再设置系统提示词（只存待定值）。
- 摘要记忆的基准会话承载 pipeline 级配置（合批间隔、回复通道、模型覆盖）与入口阶段的配置读取；case 会话在首次执行该 case 时创建。
- 带记忆对话与摘要记忆在建立会话前把 agent/角色级配置导入会话级（已有值不覆盖）：带记忆对话导入模型、压缩、记忆回溯、记忆读取开关、合批、回复通道、工具分组；摘要记忆导入模型、记忆回溯、合批、回复通道、工具分组。无记忆对话不导入，只使用会话级已有值。
- 带记忆对话在构造 pipeline 或切回角色模式时，扫描上下文目录中匹配「前缀 + agent + 角色 + topic」的消息缓存文件，取修改时间最新的一个加载；没有则新建话题会话。事件会话不参与扫描。
- 角色模式判定为新话题时，生成新的话题会话，把当前会话的整份会话级配置复制过去，旧会话直接释放（不归档、不产生版本，缓存文件留在磁盘上但不参与后续对话）。
- 系统提示词：无记忆对话使用固定默认提示词；另两条在建立或重建会话时现场组装——agent 元数据、个体识别、角色设定分别转成 markdown 后拼接，保留 agent（标识为 `0`）或全部为空/失败时回退默认提示词。
- 会话上下文的缓存与版本由 LLM 基础库负责（见 `llm.md`），pipeline 只决定会话的数量、标识与生命周期。

## 三、合批

- 每条 pipeline 一个合批生产者与消费者；摘要记忆按通道各一个，互不干扰。
- 每条消息入队时把「当前时间 + 间隔」作为截止时间写入共享的原子量，采用「只增不减」的比较交换，保证并发后推不会被较早写入覆盖。消费者按截止时间取出整批消息。
- flush 时先清空截止时间再排空队列：此期间新到的消息会设置新的截止时间，留到下一批。
- 间隔取自当前会话的合批配置（摘要记忆取基准会话），默认 3 秒；间隔为 0 时近似立即 flush。
- 批次移交给 pipeline 时，消费者只持有 pipeline 的弱引用：pipeline 被释放后消费者退出并丢弃未到期的消息。
- 上行批次打包为一条用户消息：只取文本段（递归展开复合消息，跳过附件、思考、工具等非文本内容），逐行拼成「名字: 文本」，名字为空时只保留文本。

## 四、任务队列

- 无记忆对话与带记忆对话：命令、单条消息、批次三类任务进入同一条无界队列，由单消费者串行执行。命令携带一次性回传通道，队列关闭时返回内部错误。
- 摘要记忆对话：三级队列——按通道的合批消费者、单一「批次 worker」（串行定位、写上行记录、按 case 入队）、单一「case worker」（串行执行 case）。两者都只持有 pipeline 弱引用。
- 同一 case 至多一个待执行任务：任务未开始时同 case 的新消息并入同一任务；任务执行期间到达的消息留在任务表中形成下一轮。

## 五、执行循环

三条 pipeline 的共同点：

- 每轮先取本会话可用的工具定义，再调用模型。
- 循环最多 10 轮，最后一轮执行完强制结束。
- 模型的思考内容（两类来源任一有值）累积为待写入的思考记录。
- 工具调用并发执行，结果按原顺序收集并转成工具消息回填上下文；任一工具失败会把错误汇总后结束本次循环。
- 本轮的 token 占用记录为下一次阈值判定依据；无记忆对话与带记忆对话在当前会话上保存该值，切换事件、话题切换、切回角色模式时清零。

带记忆对话的差异：

- 每次发送前检查阈值：模型上下文上限大于 0，且上次响应的 token 占用严格大于「上限 × 压缩阈值」（默认 0.8）时执行一次上下文处理。
- 上下文处理方式由事件模式与记忆读取开关决定：事件模式固定压缩；角色模式按会话的记忆读取开关选择压缩或记忆回溯。
- 压缩：只读构建上下文（不应用待定系统提示词），以「最后一条助手回复（含）」为界切出尾部，剩余部分加压缩指令交给模型总结，成功后把上下文整体重置为「压缩指令 + 总结 + 尾部消息」，新消息随后追加；总结失败则不改变上下文，继续正常发送。
- 记忆回溯：只读取出会话中「最后一条助手回复之后」的消息作为尾部，与记忆存储打包的记忆上下文拼接后整体重置；不调用模型。
- 记忆打包：先取最近 N 条，得到最旧一条的位置；若数量不足 N 直接打包返回；否则以「时间窗起点」与「该位置」的较小值作为起点，再查询该时间范围，两次结果按「时间 + 序号」去重合并（天然按时间升序）。打包为交替的用户/助手消息：跳过非文本记录、丢弃对话开始前的自身消息、连续同角色合并、以用户结尾时补一条空助手消息。
- 回复：本轮有正文才发送；把本轮及之前累积的思考与工具内容与正文合并为一条下行内容，经回复通道发送，成功后才写下行记忆。发送前校验目标身份仍被某条 pipeline 绑定在该通道上，不满足则跳过发送（不清理配置）。
- 回复通道未配置时只写记忆、不发送。

摘要记忆对话的差异：

- 不做阈值判定与压缩：每次 case 执行前用「该 case 的摘要 + 结尾 N 条原文副本」重建上下文（N 取该会话的记忆回溯条数，默认 50），重建即归档并重置。
- 回复通道取自基准会话；下行记录带该 case 与批次进入时捕获的记忆范围。
- 基准会话与已有 case 会话在 `/model` 时一并写入；新建 case 会话时优先使用内存中的模型覆盖，否则对齐基准会话的模型。

## 六、同话题判定（带记忆对话，仅角色模式）

- 每批消息进入执行循环前判定，与记忆读取开关无关，不经过执行循环、不调用工具、不读记忆。
- 当前上下文除系统消息外为空时直接判为同一件事，跳过模型调用。
- 否则把完整上下文加一条包含新消息与判定要求的用户消息，问当前会话的模型；回答去空白转大写后精确匹配 YES / NO。
- 首次失败或回答不精确时，换用更强的重试提示词再问一次（只重试一次）；两次都失败或都不精确则按同一件事处理。
- 判定为不同：生成新的话题会话、复制配置、清空 token 占用，本批消息在批次末尾追加到新会话。

## 七、命令处理

- 只有管理员（发送者在来源 channel 的管理员名单中）且内容为纯文本时才识别命令；命令回复发回来源 channel，不走回复通道；命令与命令回复不写记忆、不进入上下文。
- 分层：通道级命令（管理权限增删）在通道适配层执行一次；未命中的 `/` 文本按输入身份交给 pipeline，由 pipeline 按命令名匹配，不认识的按普通消息处理。
- 各 pipeline 支持的命令：三条都支持 `/model` 与 `/mode`；带记忆对话与摘要记忆支持 `/bind-outgoing`、`/unbind-outgoing`；仅带记忆对话支持 `/load-memory`。
- `/mode event [事件标识]`：缺省事件标识时自动生成。前两条 pipeline 释放当前会话并按目标事件重建（带记忆对话会导入配置并应用系统提示词）；摘要记忆只修改命令来源通道的事件映射（内存态，重启丢失）。`/mode role` 反向操作。
- `/bind-outgoing`：要求目标 channel 存在、且该身份已被某条 pipeline 绑定在该 channel 上；带记忆对话写当前会话，摘要记忆写基准会话。`/unbind-outgoing` 清空回复通道。
- `/load-memory <on|off>`（兼容 true/false）：只写当前会话的记忆读取开关；事件模式下写入但不生效。
- `/model <provider> <model>`：先拉取该 provider 的模型列表校验存在性，失败保持原模型；成功后写入会话模型配置（摘要记忆写基准与已有 case 会话，并记录内存覆盖）。
- 参数个数不符返回参数错误，执行失败返回错误文案；两类回复的文案前缀不同（参数错误、执行失败、成功各有固定前缀）。

## 八、记忆写入

- 写入客户端把通道记录放入队列，按「累计 10 条」或「首条入队后 100 毫秒」触发一次批量请求，并等待落盘结果；写入失败只记日志，不重试。调用方总是以强制模式提交。
- 上行：无记忆对话不写；带记忆对话在收到消息时立即写（不带 case 信息）；摘要记忆在定位成功后写（每条带所属 case）。
- 下行：无记忆对话不写；另两条在回复发送成功后写（内容取发送响应，覆盖发送时被通道补充的消息标识与时间），摘要记忆带 case 与批次记忆范围。
- 思考、工具调用、工具结果作为下行记录内容的组成部分按顺序内嵌，不单独成记录；无正文的轮次不写记录，累积内容留到有正文的轮次。
- 待回显：下行发送成功后把响应中的消息标识记入该 channel 的运行态，TTL 60 秒、懒清理；收到同标识消息时消费并丢弃。

## 九、摘要记忆 pipeline 的批次与 case

- 批次由负责该通道的合批消费者投递到批次队列；批次 worker 串行处理：取该通道当前的记忆范围快照 → 调摘要记忆定位 → 定位失败或结果未覆盖本批全部消息则丢弃整批（不写记忆、不入队）。
- 定位成功后逐条写入上行记录（带 case），并按 case 合并进待执行任务；该 case 尚未排队时才投递 case 名。
- case worker 取出某 case 的全部待执行消息后执行：重建上下文 → 执行循环 → 结束后取下一个 case。
- 批次进入时的记忆范围随任务保存，case 执行期间切换事件不会改变该次执行的摘要查询与下行写入范围。
- channel 被解绑时，该 channel 的合批生产者、待处理消息与事件映射一并清除；重新启用后该 channel 回到角色模式。

## 十、失败路径

| 场景 | 行为 |
|------|------|
| 模型调用失败（重试耗尽） | 本次执行结束；本轮用户消息已进入上下文；不发回复、不写下行记忆、不更新 token 占用 |
| 工具调用失败 | 汇总为多错误结束本次执行；此前已发送的回复与已追加的上下文不回滚 |
| 记忆回溯读取失败 | 使用空上下文继续发送 |
| 摘要记忆定位失败 | 丢弃整批消息 |
| 摘要记忆上下文重建失败 | 清空该 case 上下文，仅用本批消息执行 |
| 回复目标身份已不被绑定 | 跳过发送 |
| 记忆写入失败 | 记录日志，不阻塞对话 |
