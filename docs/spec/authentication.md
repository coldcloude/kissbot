# 认证机制

## 一、密钥与归属

公共配置的安全段提供两个密钥：通用密钥与管理密钥。二者都是单一字符串，没有用户、角色或权限模型。

| 密钥 | 使用者 |
|------|--------|
| 通用密钥 | agent 的出站客户端（记忆存储、自我认知、摘要记忆、子站）；通道服务端的 WS 握手；记忆三服务的 HTTP 接口；station 的 MCP 端点 |
| 管理密钥 | agent 的管理接口；Web 通道的 HTTP 接口（含事件推送与附件访问） |

「管理员与普通用户」的区分由「哪个端点用哪个密钥」实现：security 组件本身不判断请求方的身份，只判断其是否持有该端点要求的密钥。

## 二、传输方式

- HTTP 请求：从请求头中取密钥，去掉首尾空白后比较；头缺失、编码非法、为空或纯空白都视为缺少密钥。
- WebSocket：握手请求同样从请求头取密钥，校验失败返回 401 并拒绝建立连接；连接建立后不重复校验。
- 不识别 `Bearer` 等前缀，密钥按原样比较。

## 三、实现结构

- **校验器**：接口 + 简单实现（持有预配置密钥做字符串比较），组件可提供自己的实现。
- **HTTP 接入**：tower 的 Layer/Service 手写实现，在业务处理前拦截；通过后原样转发请求，不修改请求、不注入身份信息。
- **WS 接入**：实现 kai-ws 的握手过滤接口，失败时返回带错误文案的 401 响应。
- **配置读取**：安全段在首次访问时读取并缓存（进程级单例），此后不读取文件。

## 四、失败语义

- 缺少密钥与密钥错误都返回 401，不区分两种情况，避免暴露「这个端点需要密钥」之外的信息。
- 响应体为统一的失败外壳（成功标志为假 + 错误文案）。
- 没有 403、没有限流、没有失败计数与审计日志，也没有密钥轮换机制。

## 五、边界

- 认证只回答「请求方是否知道密钥」，不回答「它能做什么」。任何持有通用密钥的客户端都可以查询任意通道信息、绑定任意已存在的通道用户、调用任意工具。
- 校验使用普通字符串比较，不是常量时间比较。
- 密钥以明文写在公共配置中，配置文件的分发范围即为信任边界；对外暴露的服务依赖代理层与外网隔离。
