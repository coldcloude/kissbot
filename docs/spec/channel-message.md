# 消息模型机制

> 说明通道与记忆共用的消息内容模型及其在通信中的语义。结构定义见 `kissbot-api/src/message.rs`。

## 一、内容模型

同一条消息的内容是类型化的：文本、附件信息、附件响应、复合、群组加入、群组退出、用户移除、思考、工具调用、工具结果。

- **文本**：直接携带文本。
- **附件信息**：仅元信息（文件名、MIME、字节数），用于发送方向；由通道注册后转换为附件响应。
- **附件响应**：携带存储标识、传输标识与元信息，用于接收方向与推送。
- **复合**：内容项列表，可嵌套；一项消息可以同时包含文本、附件、系统事件等。
- **群组加入 / 退出 / 用户移除**：系统事件，作为消息呈现给接收方。
- **思考 / 工具调用 / 工具结果**：只出现在记忆记录的内容里，不用于通道收发；它们随所属通道记录一起保存。

## 二、消息方向

- **下行消息**（发送方 → 通道）：由发送方构造，不含消息标识与时间。
- **上行消息**（通道 → 接收方）：含消息标识、时间、通道名称与用户名、群组信息与接收者身份。
- 消息标识与时间由通道实现生成（在「下行转上行」的过程中），发送方不决定。
- 上行消息携带「接收者身份」，因为同一个 agent 可以在同一通道上绑定多个身份，接收方需要知道这条消息是发给谁的。

## 三、自身回显的识别

通道消息没有「是否本人发送」字段。Agent 发送消息成功后，把响应中的消息标识记入该通道运行态的待回显集合（60 秒 TTL、懒清理）；收到同标识消息时视为自身回显并丢弃。因此回显识别完全依赖消息标识的稳定往返，而非发送者身份比较。

记忆记录里的「是否本人发送」由写入方在写入时决定：下行记录为真，上行记录为假；它不由通道消息推导。

## 四、文本提取

Agent 处理上行消息与记忆回溯时只提取文本：递归展开复合内容，把每个文本项作为一段，其余类型跳过。因此附件、系统事件、思考与工具内容不会进入对话消息的文本部分。

## 五、系统事件语义

- 群组加入与退出既作为系统消息参与通道推送，也作为独立控制通知推送给客户端，二者顺序相反（加入先通知后系统消息；退出先系统消息后通知）。
- 用户移除只有控制通知，不产生系统消息。
- 系统事件不写入记忆记录（agent 收到后直接丢弃，不进入 pipeline）。
