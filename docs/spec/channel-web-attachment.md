# Web 通道附件存储机制

> 说明附件文件布局、上传队列、缩略图与下载的实现细节。

## 一、文件布局

每个群组一个目录，存放：

| 文件 | 内容 |
|------|------|
| `{uuid}` | 附件本体 |
| `{uuid}.metadata` | 元数据（存储标识、元信息、是否有缩略图） |
| `thumb_{uuid}` | 缩略图 |
| `.{uuid}.uploading` | 上传期间的临时文件 |

存储标识为「群组标识 / UUID」，同时用作跨组件的附件标识。

## 二、元数据与缓存

- 元数据读取使用 LRU 缓存（容量 1024），缓存未命中时读文件。
- 注册（上传完成前的写入路径）使用完整存储标识写入缓存，读取使用 UUID 部分查询缓存，两者键不一致：上传注册时写入的缓存项不会被读取命中，实际只有读路径的缓存生效。

## 三、上传

- 每个传输标识一条无界队列，配一个串行写入任务，因此同一附件的分块按到达顺序写入，不会并发写同一文件。
- 顺序语义：
  - 偏移落后于当前进度：视为重复块，返回成功与当前进度（幂等）。
  - 偏移超前：返回乱序错误与当前进度，由发送方纠正。
  - 数据长于声明大小：截断。
  - 数据短于声明大小：报错。
- 收满声明大小后把临时文件改名为正式文件，并为图片预生成缩略图、把元数据中的「有缩略图」置真。
- 最后一块的确认在改名之前发出：客户端收到成功时正式文件可能尚不存在。
- 出错时临时文件与队列任务不清理，也没有超时回收。
- HTTP 上传接口使用表单一次性提交整个文件，作为偏移 0 的单个分块写入同一队列；不校验长度、不支持分块与续传，依赖此前发消息时已完成的附件注册。

## 四、缩略图

- 仅图片可生成；按最长边等比缩放到 200×200，统一编码为 JPEG，文件名无扩展名，响应类型固定为 JPEG。
- 上传完成时预生成；缺失时按需从本体生成。
- 非图片或解码失败返回错误。

## 五、下载

- 支持单段范围请求：给出起止字节时返回 206 与范围信息，越界或起止反序按无范围处理并返回整个文件。
- 响应类型取元数据中的 MIME；没有额外的缓存控制头。
- 下载映射（传输标识 → 存储标识）在传输完成或中断后删除。

## 六、边界

- 不支持多段范围、校验和、重传与断点续传。
- 附件下载与缩略图接口与其他管理接口一样要求管理密钥；浏览器直接请求图片地址时不会携带自定义请求头，因此这类请求可能被认证中间件拒绝。
- 删除群组或用户不删除附件文件。

## 七、相关代码

- 附件存储：`kissbot-channel-web/src/attachment.rs`
- 管理接口中的上传/下载/缩略图：`kissbot-channel-web/src/http.rs`
