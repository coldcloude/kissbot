# Web 通道消息存储机制

> 说明消息文件组织、批量写入、时间重写、索引与翻阅定位的实现细节。

## 一、文件组织

- 消息按「群组标识 / 日期」组织：每个群组每天一个 JSON Lines 文件，每行一条消息记录。
- 记录内含消息标识、通道与群组身份、发送者与接收者、内容、时间。文件内没有单独的序号字段，行号即位置。
- 群组目录在首次写入时创建；读取时为每个存在的日期文件建立一个索引上下文。

## 二、批量写入

- 发送路径把记录交给批量追加器，入队即返回；追加器在「累计 100 条」或「距缓冲区创建超过 1 秒」时触发一次写出，批内保持入队顺序。
- 写文件时把整批记录序列化后一次性写出（含换行），避免索引读到半行。
- 落盘完成后依次执行：更新时间戳、更新内存日期集合、标记该文件索引过期、推送。
- 错误处理器为空实现，写失败只被丢弃；发送方已经拿到成功响应。

## 三、时间重写

- 记录的时间在落盘时统一覆盖，而非沿用发送时间。
- 若落盘时的日期与文件所属日期相同，取落盘时的当前时间；不同（跨天滞后落盘）时重写为该文件日期的最后一秒。
- 因此同一批消息的时间可能完全相同，且文件内的时间与文件日期始终一致。
- 副作用：发送响应中的时间与最终落盘时间可能不同；跨天时相差一天。

## 四、索引与日期集合

- 每个日期文件一个索引上下文（由 kai-file 提供）：分钟级时间索引、每千行字节锚点、懒更新。写入后标记过期，读取时按标记增量补齐或全量重建。
- 另外维护「群组 → 有消息的日期」内存集合，用于跨文件翻阅。该集合只在本进程写文件时补充，重启后为空，随后续写入逐步恢复；没有启动时扫描目录重建。

## 五、翻阅与定位

- **最近若干条**：从日期集合的最新日期开始逐日取文件尾部，取满数量后按日期升序返回。
- **以某条消息为锚点**：
  - 向前取：从锚点所在文件取锚点之前的部分；不足时取前一日期文件的尾部，继续向前补。
  - 向后取：从锚点之后开始；不足时取后一日期文件的头部，继续向后补。
  - 行号为文件内记录位置；新到达的消息在展示层用占位行号 0 表示，排序时视为最新。
- **按时间范围取**：把区间切成「首日尾段 + 若干整日 + 末日头段」后逐文件读取。
- 三种查询均返回带文件内行号的记录，调用方据此分页。

## 六、已知边界

- 重启后日期集合为空，跨文件翻阅在本次启动写入之前只能看到索引已能覆盖的范围。
- 向前取时若锚点行号为 1，则该文件内没有更早记录，会直接转到前一日文件。
- 删除群组或用户不删除消息文件；对应目录保留在磁盘上。

## 七、相关代码

- 消息存储与翻阅：`kissbot-channel-web/src/message_store.rs`
- 文件索引与批量追加：kai-file（位于同级目录的 kai-rs 仓库）
