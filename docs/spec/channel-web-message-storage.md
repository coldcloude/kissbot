# channel-web 消息本地存储

## 存储组织

- 消息按 `{group_id}/{date}.jsonl` 组织，每个群组每天一个文件
- 每行一条 JSON 序列化的 IncomingMessage

## 批量异步写入

- 基于 kai-file 的批量追加框架（FileObjectAppender）：append 只入队即返回，按批量大小或超时触发落盘
- 文件写入上下文按 key（group_id + date）管理，使用弱引用持有，不活跃 key 的上下文自动释放

### 消息时间归属

- 消息时间以实际写入时间为准，在落盘时统一打时间戳
- append 分为入队和落盘两段：消息按发送时的日期确定文件 key，但落盘可能滞后到第二天，此时落盘时间与文件 key 的日期不一致
- 因此落盘时间若与 key 日期不同，时间戳重写为 key 当日的最后一秒（23:59:59），保证文件内消息时间与文件日期一致

## 落盘后处理

- 落盘完成后依次执行：
  - 通知 messenger 执行消息推送（先存后推的触发点，见 [channel-web-message.md](channel-web-message.md)）
  - 更新内存日期集合（group → 有消息的日期，有序集合）
  - 标记该 key 的文件索引过期

## 查询

- 基于 kai-file 的文件索引（见 kai-rs/docs/kai-file.md），支持：
  - 最近 N 条
  - 以一条消息（文件 + 行号）为锚点，查询其之前 / 之后的 N 条消息
  - 按时间范围查询
- 以消息为锚点的查询支持跨文件：本文件不足 N 条时，借助内存日期集合定位前 / 后日期的文件，逐文件补齐数量
