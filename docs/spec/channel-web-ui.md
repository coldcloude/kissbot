# Web 通道前端机制

> 说明 `kissbot-channel-web-ui` 的页面结构、数据流、状态管理与交互约定。界面设计见 `docs/design/components-design/ui-ux-design/kissbot-channel-web/README.md`。

## 一、页面结构

- 未连接时显示登录页：后端选择（自定义地址 + 预置后端列表）、管理员密钥输入、连接按钮；错误就地显示（地址为空、协议非 http(s)、密钥为空、连接失败）。
- 连接后显示主界面：顶部栏（应用名、管理员名下拉菜单）、左侧会话列表、右侧内容区。
- 右侧内容区在三种视图之间切换：消息区、群组管理面板、用户管理面板；后两者为整块替换，不弹窗。
- 消息区包含会话标题、消息列表、待发附件预览、单行输入框、附件按钮、发送按钮（有待发附件时按钮文案显示上传）。
- 消息中的图片显示缩略图，点击打开全屏遮罩查看原图，点击遮罩关闭；文件类附件显示下载链接。

## 二、后端地址来源

- 预置后端列表放在前端静态资源目录下的独立配置文件（`public/backends.json`），运行时通过同路径请求加载，不打进构建产物。
- 加载后逐条校验名称与地址类型；任何异常（请求失败、JSON 非法、字段类型不符）都降级为空列表，此时只显示自定义输入。
- 部署时可直接替换构建产物中的该文件来切换环境，不需要重新构建。
- 请求的后端地址由用户选择或输入；地址为空时请求退化为相对路径，此时才依赖开发服务器的代理。

## 三、认证与事件订阅

- 所有请求携带管理员密钥请求头。
- 事件订阅使用基于 fetch 的推送客户端，支持携带自定义请求头；断线由客户端库自动重连。
- 解析失败的事件按 keep-alive 忽略。
- 不使用 WebSocket，全部交互走 HTTP 与事件推送。

## 四、状态管理

全部状态集中在根组件的 state 与 ref 中，没有状态库、路由与持久化：

- 用户表与群组表：群组表由后端返回的群组与前端按「单聊前缀 + 用户标识」构造的虚拟会话合并而成。
- 消息：按会话分组，组内再按日期分组；每组的消息按文件内行号升序，占位行号 0 视为最新。
- 翻页游标：每个会话保存「日期 + 行号」，用于向前加载。
- 去重集合：全局记录已加载的消息标识，推送与分页结果都按它去重。
- 未读计数：按会话维护的计数表，打开会话时清零，不持久化、不跨刷新。
- 当前视图：消息区与两个管理面板之间的切换状态。

## 五、会话列表

- 单聊会话显示对端用户名并标记为单聊，普通群组显示群组名并带群组标记。
- 排序依据是「最后一条已加载消息的时间字符串」降序（字符串比较即时间序）；尚未加载消息的会话排在最后。
- 未读数大于 0 时显示徽标，超过 99 显示省略；切换到该会话时清零。
- 未加入的群组同样展示，但输入区禁用。

## 六、消息区

- 首次打开会话加载最近 20 条；列表滚动到距顶部 50 像素以内时加载更早的 10 条，加载中在顶部显示提示。
- 加载历史后不校正滚动位置；仅在新增消息较少（小于 5 条）时自动滚到底部。
- 推送到达的消息按时间前 10 位归入日期分组；本地乐观插入的已发送消息使用响应里的时间。
- 左右对齐只对「本地刚发出」的消息生效：前端在乐观插入时标记，后端不下发该标记。因此 agent 回复与其他用户消息都在左侧，左侧标签显示用户标识。
- 渲染规则：文本显示为文本；附件响应按 MIME 判断图片或文件；群组加入/退出与用户移除显示为居中系统提示；复合消息按顺序渲染子项；未识别的类型不渲染。

## 七、群组与用户管理

- 群组管理：新建（群名 + 勾选用户，提交时自动把管理员加入成员）、重命名（下拉选择普通群组）、管理成员（界面只支持添加，后端支持移除）、群组列表（显示成员标识）与删除（无二次确认）。单聊群不在面板中出现。
- 用户管理：新建（提示用户标识由系统生成且会自动建立与管理员的单聊）、列表、重命名（遮罩弹层）、删除（浏览器确认框）；删除后本地同时移除该用户与其单聊会话。
- 管理操作成功后只更新本地状态，不重新拉取通道信息。

## 八、附件上传

1. 用户选择文件后，发送一条带附件元信息的消息；
2. 后端注册附件并在响应中返回传输标识；
3. 前端按传输标识通过上传接口提交文件数据。

## 九、构建与部署

- `npm run build` 先做类型检查再由构建工具产出静态文件。
- 后端不托管静态文件；生产环境需要由独立的静态服务器或反向代理提供构建产物，并保证事件流与接口请求指向同一个 Web 通道后端。
- 替换静态文件中的后端列表即可切换环境，无需重新构建。
