# Web 通道机制

> 说明 Web 通道后端的配置仓库、消息收发、推送与附件实现。设计意图见 `docs/design/components-design/kissbot-channel-web.md`。

## 一、进程与配置

- 启动时读取公共配置的 Web 通道段：通道标识、管理员名称、用户与群组仓库文件路径、消息目录、附件目录、WS 监听地址、HTTP 监听地址；配置读取失败直接退出。
- 构造通道实现的创建入口并注册到框架，同时启动 WS 服务端与 HTTP 服务；任一服务退出即进程结束。
- HTTP 全部路由叠加管理密钥认证与宽松 CORS；WS 握手使用通用密钥。
- 用户与群组仓库是可写 JSON：通道标识、管理员名称、用户表、群组表与两个自增序号。写入方式为「持写锁改内存 → 整份序列化 → 覆盖写文件」；文件不存在时先用内存默认值，首次写操作才落盘。

## 二、用户与群组模型

| 实体 | 标识 | 说明 |
|------|------|------|
| 管理员 | 固定名称 | 操作员身份，不出现在通道用户表中，因此 agent 无法绑定；不参与 WS 分发，只通过事件推送查看消息 |
| 普通用户 | `u` + 数字 | 由管理员创建，序号持久化、删除后不复用；作为 agent 在通道上的身份 |
| 群组 | `g` + 数字 | 显式群组，成员含管理员与若干用户 |
| 单聊群 | `a_` + 用户标识 | 管理员与该用户的私聊，不写入仓库，按前缀在运行时派生（服务端与前端各自构造） |

- 单聊群拒绝改名、改成员与删除（按前缀判断）。
- 创建用户只分配序号并写仓库，不显式创建单聊群；删除用户时从所有群组成员中移除该用户，再上报用户删除事件。
- 创建群组时给每个非管理员成员上报「加入」事件；增减成员时先给新增成员上报「加入」、再给移除成员上报「退出」；删除群组时给每个非管理员成员上报「退出」。改名只更新仓库，不上报事件。
- 删除群组或用户不会删除历史消息与附件文件。

## 三、消息发送与落盘

```
校验发送者与目标群组
→ 注册附件（若有），得到存储标识与传输标识
→ 分配消息标识与时间（标识 = 时间串 + 6 位自增序号）
→ 按发送时间的 UTC 日期确定日期文件
→ 交给批量追加器：入队即返回成功
落盘时：
→ 统一重写这批消息的时间：落盘日期等于文件日期时取当前时间，否则重写为该文件日期的最后一秒
→ 更新内存中「群组 → 有消息的日期」集合
→ 标记该文件的索引过期
→ 先向所有事件订阅者广播消息
→ 再按当时的群组成员向各用户连接分发
```

- 批量追加器按「1 秒」或「100 条」触发一次落盘；错误处理器为空实现，写失败被静默吞掉。
- 发送响应早于落盘与推送：调用方拿到成功时消息可能尚未写盘，其他成员也可能尚未收到。
- 分发时成员按当前仓库计算，而非按发送时的成员。
- 分发规则：普通群组分发给除管理员外的每个成员（发送者本人在成员中时也会收到）；单聊群中管理员发送时只发给该用户，用户发送时只回显给该用户自己；管理员永不进入用户连接的分发。
- Agent 收到自己的回显后按消息标识识别并丢弃，通道不做「是否本人」判断。

## 四、事件推送

- 每个订阅连接分配一条无界队列，全局广播（不按群组过滤），载荷为落盘后的消息。
- 每 15 秒发送一次 keep-alive 注释。
- 发送采用「尝试发送，失败即剔除该连接」策略：慢客户端会丢消息，但不会阻塞写路径。
- 断线期间的消息不补发，界面通过历史查询补齐。

## 五、历史翻阅

- 消息按「群组 / 日期」组织为日文件，每行一条记录并带文件内行号。
- 最近若干条：按日期集合从新到旧逐日取尾部，取满后按日期升序返回。
- 以「日期 + 行号」为锚点向前 / 向后取：本文件内取锚点之前 / 之后，数量不足时借日期集合跨文件补齐（向前取前一日尾部，向后取后一日头部）。
- 按时间范围取：把区间切成按日段后逐文件读取。
- 日期集合只记录本进程写过的日期，重启后为空；之后的写入会补充，因此重启后的翻阅范围取决于本次启动后写入过的日期与文件索引自身的能力。

## 六、附件

- 按群组目录存放本体、元数据与缩略图三类文件，以及上传期间的临时文件；存储标识由群组标识与 UUID 组成。
- 元数据读取走 LRU 缓存（容量 1024）。注意：注册写入缓存使用完整标识、读取使用 UUID 部分，两者不一致，因此写路径的缓存项不会被命中。
- 上传按传输标识维护一条无界队列与一个串行写入任务，因此同一附件的分块严格按到达顺序写入；偏移落后视为重复（返回成功与当前进度）、偏移超前视为乱序（返回乱序错误与当前进度）、数据长于声明时截断、短于声明时报错。
- 收满声明大小后把临时文件改名为正式文件，并为图片预生成缩略图；错误时临时文件不清理。
- HTTP 上传使用表单一次性提交整个文件，作为偏移 0 的单个分块写入同一队列，依赖此前发消息时已完成的注册。
- 缩略图按最长边 200×200 等比缩放，统一输出 JPEG；非图片或解码失败返回错误。
- 下载支持单段范围请求（越界或反序按无范围处理），返回对应状态码与范围信息；无范围时返回整个文件。

## 七、管理接口

管理接口提供：会话信息（管理员名称、用户表、群组表）、发送消息、三类历史翻阅、群组增删改名与成员增减、管理员改名、用户增删改名、附件上传/下载/缩略图、事件订阅。全部响应为统一外壳；业务失败以成功响应加失败标志表达，认证失败返回 401。

## 八、标识与时间

- 连接标识、消息序号、传输标识、用户与群组序号都是进程内计数器；消息标识的时间部分为秒级时间串，序号 6 位、溢出后归零，因此同秒内大量消息或同秒重启可能产生重复标识。
- 时间全部以 UTC 生成，格式为不带时区标记的「年-月-日 时:分:秒」；前端按浏览器本地时区解析显示。
