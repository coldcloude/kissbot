# 通道框架机制

> 说明通道服务端的连接、绑定、路由与附件传输实现。设计意图见 `docs/design/components-design/kissbot-channel.md`。

## 一、库结构

- **Messenger 接口**：通道实现需提供的能力——读取通道信息（通道标识、用户表、各用户的群组表与名称）、发送消息并返回消息标识、时间与内容转换结果、写入上传分块、解析下载请求并分配传输标识、启动下载分块推送。
- **注册机制**：通道实现提供一个创建入口，框架在注册时调用它，并把服务端自身以弱引用注入实现方。实现方通过该弱引用回调框架（上报上行消息、群组事件、用户删除、附件数据）。
- **通道服务端**：WS 服务端 + 连接表 + 绑定表 + 上传/下载两张传输路由表 + 各 messenger 实例表。

## 二、连接管理

- 监听配置的 WS 地址，握手阶段用安全组件的过滤器校验通用密钥，失败返回 401 且不建立连接。
- 每个连接分配一个进程内自增的连接标识（从 0 开始、不复用），不暴露给客户端，仅作连接表键与绑定表的值。
- 连接建立时启动心跳处理器，间隔 5 秒（二进制消息）；具体超时判定在 kai-ws 内。
- 连接关闭时先移除连接记录，再遍历所有 messenger 的绑定表，把指向该连接标识的绑定全部删除。遍历与删除分步执行并循环到没有候选，避免并发映射的重入问题。
- 框架不提供自动重连；断线期间的上行消息不会补发。

## 三、绑定

- 绑定表按 messenger 组织为「用户标识 → 连接标识」。
- 绑定前校验该用户出现在 messenger 上报的用户表中；重复绑定时，同连接幂等成功、其它连接报「已绑定」。
- 解绑、发送消息、下载请求都校验「该用户当前绑定 == 本连接」。
- 一个连接可以绑定多个用户，一个用户在同一 messenger 上只能被一个连接绑定。
- 绑定不持久化，连接关闭即失效。

## 四、请求与推送

客户端请求共有六类：查询通道信息、绑定、解绑、发送消息、上传分块、下载请求。服务端推送共有三类：上行消息、群组事件通知、用户删除通知。

- **通道信息查询**：不做绑定校验，只要求连接已认证；返回 messenger 标识、用户表（含各用户加入的群组与名称）。
- **发送消息**：校验 messenger 存在、发送者用户绑定在本连接；调用 messenger 发送；响应中的内容已被转换为带存储标识与传输标识的形态；框架随后递归遍历响应内容，把每个附件的传输标识登记到上传路由表；返回响应。
- **上行消息**：messenger 上报「接收者身份 + 消息」，框架按接收者绑定找到连接，以独立推送帧发出（帧内含接收者身份与完整消息）。接收者未绑定时记录日志并丢弃。
- **群组事件**：加入时先推「加入」控制通知、再推系统消息；退出时先推系统消息、再推「退出」控制通知。被通知用户未绑定时整个处理失败并记录日志。
- **用户删除**：先从绑定表移除该用户，再推送删除通知；未绑定时只记日志、不通知。
- 请求处理统一包装：成功返回成功状态与负载，失败返回错误状态与空负载并记录日志；事件类处理的失败也只记录日志，不向调用方传播。

## 五、附件传输

- 消息中的附件先以元信息（文件名、MIME、字节数）出现；注册后转换为「存储标识 + 传输标识」的响应形态，并递归处理复合内容里的嵌套附件。
- 存储标识是附件的永久标识，传输标识是本次传输的路由标识（进程内自增），上传与下载各维护一张传输表。
- 二进制帧布局：通用帧头（序号、类型、状态码）+ 传输标识 + 本块大小 + 块偏移 + 数据；数据起始偏移为 28 字节。
- **上传**：客户端按传输标识连续发送分块；服务端解析头，查上传表得到 messenger 与声明的总大小，交给 messenger 写入；把写入结果（当前进度、错误码、错误信息）作为该帧序号对应的响应返回；当「已写入大小达到声明总大小」或写入失败时删除该传输项。框架不做乱序纠正，顺序与幂等由 messenger 实现负责。
- **下载**：客户端带存储标识请求下载头，框架先校验该用户绑定本连接；messenger 返回附件信息并为本次下载分配新的传输标识；框架登记下载表、先返回下载头响应，再调用 messenger 启动推送。messenger 逐块向框架申请预组帧（框架按传输标识找到对端连接、取新序号、预写帧头并返回可追加缓冲），框架发送二进制帧并等待该序号的确认；确认错误或传输失败即停止；最后一块或出错后删除传输项。
- 传输没有校验和、没有重传、没有断点续传；中断后只能重新发起（下载会得到新的传输标识）。声明的大小是唯一的完成判据。

## 六、并发与错误

- 连接表、messenger 表、两张传输表均为并发映射；连接标识与序号为原子量。
- 数据面的临界区只做查表，取得所需引用后立即释放守卫再 `await`。
- 同一连接上的不同请求由 kai-ws 并发处理，请求与响应靠序号关联，下载分块靠一次性确认通道关联。
- 错误类型覆盖连接、协议与附件传输；处理器把错误转为错误状态响应，不中断连接。
