# 记忆索引机制

> 说明记忆基础库的内存索引与查询定位。写入与通知见 `memory-store.md`，文件布局见 `memory-directory.md`。

## 一、索引结构

索引按「agent + 记忆范围 + 日期文件」维护，每个文件一份：

- **时间索引**：分钟粒度的有序映射，记录每一分钟覆盖的字节区间与行号区间，用于按时间范围快速定位。
- **页索引**：每 1000 行记录一个起始字节位置，用于按行号定位。
- **文件状态**：总行数、末尾字节位置、最后一条记录的时间与序号。

索引器是进程级单例，写入路径与查询路径共用同一实例。

## 二、懒更新

- 索引不监听文件变化，只接受写入方主动标记：
  - **增量失效**：下次查询时从记录的末尾字节继续正向扫描，补齐新增记录。
  - **全量失效**：清空该文件索引并重新扫描。
- 索引更新失败时恢复失效标记，下次查询重试。
- 重建发生在文件被整文件重写之后（乱序数据的强制写入）。

## 三、日期集合

- 另维护「agent + 记忆范围 → 有数据的日期集合」，用于「最近若干条」跨文件查询。
- 首次查询前会懒扫描该 agent 的记忆存储目录，按「目录名以四位数字年份开头 + 连字符 + 后缀精确匹配」收集文件；扫描失败忽略。
- 后续由写入路径在落盘后增量补充日期。集合常驻内存、没有容量上限与淘汰。

## 四、查询

- **按时间范围**：把区间切成按日段（同日一段；跨日为首日尾段、若干整日、末日头段），逐文件用分钟索引定位字节范围后顺序读取，再按精确时间字符串过滤。结果按天分组，某天没有记录时也会返回一个空组，组的顺序按日期升序。
- **首 N 条 / 末 N 条 / 某行之后 / 某行之前**：用页索引与文件状态定位。
- **最近 N 条**：从日期集合的最新日期开始逐文件取尾部，取满数量即停，结果按日期升序返回。
- 查询结果统一携带文件内全局行号，用于分页。

## 五、并发

- 索引结构使用并发映射：文件键 → 每文件读写锁；失效集合也是并发集合。
- 单文件更新串行、跨文件并行。
- 写入方在写入后显式刷新文件，读取方才能立即看到新记录。

## 六、相关代码

- 索引与查询：`kissbot-memory/src/index.rs`
- 索引底层（时间分桶、页锚点、位置读取）：kai-file（同级目录的 kai-rs 仓库）
- 写入侧的失效标记：`kissbot-memory-store/src/record.rs`
