# 记忆存储机制

> 说明记忆存储服务的写入、顺序保证、批量、索引联动与通知。文件布局见 `memory-directory.md`，索引见 `memory-index.md`。

## 一、写入分组

请求携带一批通道记录与一个强制标志（大于 0 视为强制）。服务端先按「agent + 记忆范围 + 日期」分组：同一文件的多通道记录合并为一次写；分组为空时直接返回成功。

## 二、顺序检查

- 对每个文件 key 取写锁，读取或复用文件状态（最后一条记录的序号与时间）。
- 本批最早时间早于文件最后时间且未强制时，整批拒绝并返回顺序错误（携带文件 key、文件最后时间与本批最早时间），不写任何文件。
- 检查完成后释放锁；检查与真正写入不在同一临界区，因此并发下仍可能出现乱序，最终由写入器的整文件重写纠正。

## 三、批量缓冲

- 写入交给通用追加入口：按 key 分桶缓冲，同一 key 的多次投递合并为一批。
- 触发条件为「累计 10 条」或「首条入桶后 100 毫秒」，先到者生效。
- 写出时按 key 取写锁，桶内按投递顺序拼接，每个 key 一次写。
- 每次投递返回一个一次性承诺；写入成功批量兑现成功，失败则该批全部兑现失败并回调错误处理（默认只记日志）。服务端等待全部承诺后返回，任一失败返回错误。

## 四、写入器

每个 key 一个写上下文，缓存文件状态：

```
按已有最后序号递增分配序号 → 按（时间, 序号）排序
  ├─ 本批最早时间早于文件最后时间（强制写入的乱序数据）
  │    → 读出全部旧记录与本批合并排序
  │    → 序号从 1 重新编号
  │    → 覆盖写整个文件
  │    → 索引标记全量失效
  └─ 否则
       → 逐条递增序号并写一行
       → 更新文件状态
       → 索引标记增量失效
两种情况都在写完后显式刷新，再发布通知
```

- 序号在文件内单调递增，但整文件重写会重排，因此序号只表示文件内的物理位置。
- 每个 key 的写上下文锁常驻（回收钩子为空实现），文件状态缓存长期保活。
- 不按消息标识去重：重复推送会产生重复记录。

## 五、通知

- 写入并刷新完成后，本批记录按通道分组，每个通道一条通知，内容为「agent、记忆范围、通道三元组、该通道在本批中最后一条记录的位置与是否本人」。
- 通知只携带位置，不含记录内容。
- 进程内无界队列交给单独的广播任务串行消费，逐连接发送；未启动通知服务时通知被丢弃；序列化失败记错误并跳过。
- 向某连接发送失败即移除该连接；无重试、无补发、无持久化。单个连接的握手或读写失败只记告警，服务继续接受连接。
- 心跳间隔 5 秒，单连接消息队列容量 100。

## 六、查询

- 时间范围查询与最近条数查询都走内存索引（见 `memory-index.md`），返回按天分组、组内升序的结果；最近条数的结果按日期升序。
- HTTP 层统一响应外壳与密钥认证，失败统一返回错误状态。
- 查询不按通道过滤，返回该记忆范围内全部通道的记录。

## 七、配置

服务配置包含 HTTP 监听地址、通知监听的地址与端口；记忆根目录复用记忆基础库的配置。通知监听与 HTTP 监听是两个独立端口。
