# 系统设计文档

## 一、组件体系

### 1. 智能体（Agent）
系统的中枢。将来自消息通道的消息加工为 LLM 可用的上下文，通过 agentic loop 调用 LLM 执行操作、生成回复。支持三种运行模式：问答模式（单次问答）、工程模式（持续完成一件事）、自主模式（持续收集信息并与他人交互）。负责在 agentic loop 外推送记忆到记忆存储模块，在 agentic loop 内由 LLM 通过 tool call 从记忆结构模块查询记忆。

### 2. 消息通道（Channel）
连接外部系统的桥梁。定义统一的 Messenger 接口（通讯应用接入标准）和 Channel 接口（消息收发通道），提供通道管理器作为核心协调层。具体的通讯应用接入由通道实现模块完成（如 Web、QQ、Matrix 等）。

**通道实现模块**：实现 Messenger 和 Channel 接口，负责连接具体的外部系统（如 Web 页面、QQ 等），实现用户管理、群组管理、消息收发、附件管理等功能。每个实现模块对应一种通讯应用，可包含后端服务和前端界面。

### 3. 记忆系统
由三个层次组成：

**记忆基础模块**：定义记忆文件系统的目录结构，提供目录管理和索引查询功能，供其他记忆模块使用。按 agent ID → 年 → 角色 → 日期组织文件，通过标识文件判断 agent 目录有效性，支持按时间范围快速查询。

**记忆存储模块**：收集智能体和消息通道的全部原始消息（包括 channel 文本、思考内容、工具调用三种类型），按统一格式持久化存储，提供记忆推送和查询 API。有新数据时通知各已连接的记忆结构模块。

**记忆结构框架**：定义记忆结构构建的标准接口。具体实现由独立的记忆结构实现模块完成。

**记忆结构实现模块**：对记忆存储模块中的记忆片段构建特定索引结构（如摘要索引、最近记忆索引等），提供记忆搜索工具供 agent 通过 tool call 调用。

### 4. 自我认知模块（Memory-Ego）
管理 agent 的双重自我认知设定。每个 agent 有一份客观设定（身份标识、用户识别信息）和多份角色设定（角色扮演信息、角色扮演关系信息）。通过 API 进行管理，agent 在自主模式启动时读取自我认知信息并构建到系统消息中。

### 5. API 定义模块
定义各模块间通信的标准数据结构和统一的响应格式。是模块间数据交换的契约层，确保跨模块通信的数据类型一致。通过泛型 trait 保证并发类型和序列化类型的编译时一致性。

### 6. 工程管理模块
为 agent 的工程模式提供支持。管理工作区目录结构、职位配置、笔记，封装文件操作（读/写/编辑）、命令执行等工具供 agent 使用。

### 7. 管理界面
提供 Web 界面的管理工具集，包括：
- **智能体配置界面**：配置 agent 使用的 LLM API、工具、技能，以及各类组件地址
- **记忆管理界面**：查看和管理记忆存储文件，配置记忆推送

## 二、运行流程

### 2.1 消息上行流程（外部用户 → agent）
```
外部系统（如 Web 页面）发送消息
  → 通道实现模块接收消息，保存附件（如有），构建消息记录
  → 通过回调通知通道管理器将消息入队
  → 通道管理器处理消息队列：
      ├─ 推送消息到记忆存储模块
      └─ 通过 WSS 将消息发送给 agent
  → agent 接收消息，加入会话上下文
  → （在 agentic loop 外）将消息推送到记忆存储模块
  → agentic loop 开始处理
```
目的：将外部用户的消息经过通道传达到 agent，由 agent 在 loop 中处理并生成回复。

### 2.2 Agentic Loop（核心执行循环）
```
1. 接收消息（来自通道或自主触发）
2. 将消息添加到会话/上下文
3. （在 agentic loop 外）将消息推送到记忆存储模块
4. 检查上下文是否需要压缩或重置
   ├─ 需要：执行 LLM 压缩生成墓碑消息，或丢弃已推送对话从记忆结构模块重新读取
   └─ 不需要：继续
5. 构建完整的 LLM 上下文（系统消息 + 对话消息）
6. 调用 LLM API
7. 处理 LLM 返回
   ├─ 有 tool call → 执行 tool
   │   ├─ 推送 tool 调用和结果到记忆存储模块（在 agentic loop 外）
   │   └─ 回到步骤 5
   └─ 无 tool call → 生成最终回复
8. （在 agentic loop 外）将思考内容推送到记忆存储模块
9. 将回复发送到消息通道
10. （在 agentic loop 外）将回复推送到记忆存储模块
11. 等待下一条消息或自主触发
```
目的：将消息加工为 LLM 可用的上下文，循环调用 LLM 执行操作直至生成回复，过程中推送所有数据到记忆系统。

### 2.3 消息下行流程（agent → 外部用户）
```
agent 生成回复消息
  → 通过 WSS 发送到通道管理器
  → 通道管理器接收，按 channel_id 查找对应 Channel 实例
  → 消息入队
  → 通道管理器处理消息队列：
      ├─ 推送消息到记忆存储模块
      └─ 调用 channel 的发送方法发送到外部系统
           → 通道实现模块保存附件后发送
```
目的：将 agent 的回复经通道送达外部系统的目标用户或群组。

### 2.4 Agent 绑定流程（接入消息通道）
```
agent 通过 WSS 发送绑定请求（指定 messenger_id 和 user_ids）
  → 通道管理器验证用户身份
  → 对每个用户，查询其所在的群组列表
  → 为每个 (用户, 群组) 组合创建 Channel 实例
  → 注册消息到达回调和群组变化回调
  → 所有 Channel 实例加入全局索引
  → 通过 WSS 返回绑定确认（含所有 channel 信息）
```
目的：agent 接入通道，建立与外部系统的通信连接。

### 2.5 记忆存储流程
```
消息产生后，通过两条路径进入记忆存储模块：
路径一（由消息通道推送）：
  通道实现模块接收外部消息 → 通道管理器消息队列 → 发送到记忆存储模块
路径二（由 agent 推送）：
  agent 产生思考/工具调用/回复 → 推送到记忆存储模块

记忆存储模块收到新数据后：
  → 将记录写入文件
  → 通过 WSS 通知所有已连接的记忆结构实现模块
```
目的：将系统中所有交互产生的原始信息完整保存，形成 agent 活动的完整记录。

### 2.6 记忆查询流程（agent 通过 tool call 查询记忆结构）
```
agent 在 agentic loop 内
  → LLM 生成 tool call（调用记忆结构模块的搜索工具）
  → agent 执行 tool call，查询记忆结构模块
  → 记忆结构实现模块从自己的索引中检索记忆
  → 返回结构化的记忆片段
  → agent 将记忆片段加入当前上下文继续处理
```
目的：agent 在对话过程中自主检索历史记忆，用于辅助当前对话。

### 2.7 自我认知读取流程（自主模式 agent）
```
agent 启动自主模式
  → （在 agentic loop 外）查询自我认知模块
  → 读取 agent 的客观设定（身份标识、用户识别信息）
  → 如果指定了角色，还需读取角色设定（角色扮演信息、角色扮演关系）
  → 将获取的自我认知信息构建到系统消息中
  → 进入 agentic loop
```
目的：agent 在自主模式中获得自我认知，知道自己是谁、面对什么用户、扮演什么角色。

### 2.8 上下文重置流程（自主模式/工程模式）
```
触发条件：上下文超长 / 长时间无消息 / 长时间未重置
  → 将当前所有消息存入记忆存储模块
  → 清除当前上下文
  → 从记忆结构模块重新读取近期记忆
  → 使用读取到的记忆重新构建上下文
  → 继续 agentic loop
```
目的：防止上下文超长影响 LLM 处理质量，通过归档旧对话、加载记忆摘要来保持上下文精简。

### 2.9 自主模式主动行为流程
```
agent 空闲状态
  → 空闲计时器超过配置的超时时间
  → 加载自主运行目标（从自我认知模块获取）
  → 根据目标进行信息收集或输出
  → 将结果推送到记忆存储模块 / 发送到消息通道
  → 回到空闲状态
```
目的：agent 在无人交互时仍能按预定目标自主收集和输出信息。

### 2.10 群组变化通知流程
```
通道实现模块检测到用户加入或离开群组
  → 调用通道管理器注册的群组变化回调
  → 通道管理器通过 WSS 将变化事件发送给 agent
  → agent 更新本地的通道列表
```
目的：让 agent 动态感知通道中群组成员变化。

### 2.11 附件下载流程
```
agent 通过 WSS 发送附件下载请求（携带 key）
  → 通道管理器根据 key 调用对应通道实现模块的附件获取接口
  → 获取附件数据
  → 通过 WSS 将附件数据返回给 agent
```
目的：agent 获取历史消息中附件的原始数据。

## 三、组件间通信

### 3.1 通信总览

| 发送方 | 接收方 | 协议 | 通信内容 | 通信时机 |
|--------|--------|------|----------|----------|
| agent | 消息通道 | WSS | 绑定请求、下行消息(回复/思考)、附件下载请求、心跳 | agent 启动时绑定；有消息回复时；需要附件时 |
| 消息通道 | agent | WSS | 上行消息(用户消息)、群组变化通知、附件数据、心跳 | 外部消息到达时；群组变化时；agent 请求附件时 |
| agent / 消息通道 | 记忆存储模块 | HTTPS | 推送记忆记录（channel 文本 / 思考 / 工具调用） | 每条消息产生时 |
| agent | 记忆结构实现模块 | HTTPS（tool call） | 记忆查询请求 | agentic loop 内 LLM 调用记忆搜索工具时 |
| agent | 自我认知模块 | HTTPS | 读取自我认知信息 | agent 自主模式启动时；上下文重置时 |
| 记忆存储模块 | 记忆结构实现模块 | WSS | 新数据通知 | 记忆存储模块收到新记录时 |
| 记忆存储模块 / 记忆结构实现模块 | — | 文件系统 | 共享读写记忆文件 | 持续 |
| 智能体配置界面 | agent 后端 | HTTPS | agent 配置管理 | 用户操作配置界面时 |
| 记忆管理界面 | 记忆存储/结构/自我认知模块 | HTTPS | 记忆查看和管理 | 用户操作管理界面时 |
| 通道前端界面 | 通道实现模块后端 | HTTPS | 用户收发消息 | 用户操作聊天界面时 |

### 3.2 通信协议说明

**WSS 协议**：用于需要实时双向通信的场景。agent 与消息通道之间通过心跳维持连接；记忆存储模块与记忆结构实现模块之间用于新数据推送通知。

**HTTPS 协议**：用于请求-响应模式的通信。所有 API 输入参数均放在 JSON 请求体中，路径仅用于路由到具体处理函数。

**文件系统共享**：记忆存储模块和记忆结构实现模块共享同一文件系统根目录。记忆存储模块写入数据后，记忆结构实现模块通过 WSS 通知了解新数据到达并读取处理。

### 3.3 关键通信约束

- **agent 与记忆系统的交互区分两种模式**：
  - agentic loop 外：直接调用 API 读取自我认知设定、推送记忆到存储模块
  - agentic loop 内：由 LLM 通过 tool call 从记忆结构模块查询记忆
- **消息通道不存储历史消息**：所有历史消息由记忆存储模块保存
- **记忆不按通道区分**：所有通道的记忆按时间顺序混合存储
- **所有 HTTPS 和 WSS 客户端支持自定义可信证书文件配置**，允许使用自签名证书
