# kissbot-channel-web 前后端联调集成测试

## 环境准备

1. 启动后端服务（kissbot-channel-web）
2. 启动前端 dev server（kissbot-channel-web-ui，Vite 代理 `/api` → 后端地址）
3. 使用 agent-browser 技能模拟浏览器操作

### 后端配置参考

`kissbot-channel-web-config.json` 中 `messenger_repo` 指向的配置文件需包含测试数据：
- 至少 2 个普通用户（user-1, user-2）
- 至少 1 个多人群组（含 admin + 部分 user）
- admin_user 单聊群组由系统自动生成

`api` 配置段中 `memory_store_url` 为空（绕开记忆系统）。

## 测试用例

### TC-01：登录页展示与连接

**前置**：页面加载
**步骤**：
1. 打开登录页
2. 验证页面显示应用名称 "Kissbot Web Chat"
3. 验证显示预置后端 URL 列表（至少 3 个选项，大字名称 + 小字 URL）
4. 验证有 Admin Key 密码输入框
5. 验证有"连接"按钮
6. 选择第一个后端 URL，输入正确 Admin Key，点击连接
7. 验证成功进入主界面

**预期**：
- 登录页各元素正确渲染
- 连接成功后进入聊天主界面

### TC-02：登录失败

**前置**：页面加载
**步骤**：
1. 输入错误的 Admin Key
2. 点击连接

**预期**：显示错误提示，不进入主界面

### TC-03：主界面布局

**前置**：成功连接
**步骤**：
1. 验证顶部标题栏显示 "Kissbot Web Chat" + 管理员下拉菜单
2. 验证左侧显示会话列表（admin-user 单聊显示用户名，多人群组显示群组名 + `群组` 标记）
3. 验证右侧默认显示"选择一个会话"
4. 验证管理员下拉菜单含三项：重命名管理员、群组管理、用户管理

### TC-04：会话列表显示

**前置**：成功连接，有配置数据
**步骤**：
1. 验证会话列表项数等于 `users.length + groups.length`
2. 验证 admin-user 单聊组显示对应用户名（不是 group_id）
3. 验证多人群组显示群组名 + `群组` 标记
4. 验证列表按最新消息时间降序排列
5. 验证未读消息数在右侧显示

### TC-05：发送文本消息

**前置**：选择一个可发送的会话（admin-user 单聊组或已加入的多人群组）
**步骤**：
1. 在输入框输入文本
2. 点击发送（或 Enter）
3. 验证消息出现在消息列表中，靠右显示（is_self=1）
4. 验证 SSE 推送的回复消息正确显示，靠左显示（is_self=0）
5. 验证会话列表的排序和未读计数更新

### TC-06：消息展示——Text 类型

**前置**：收到或发送了 Text 消息
**步骤**：
1. 验证消息中文本内容直接显示
2. 验证 admin 消息靠右（蓝色气泡），user 消息靠左（灰色气泡）

### TC-07：消息展示——AttachmentInfoResponse 图片

**前置**：收到图片消息
**步骤**：
1. 验证显示缩略图（`<img>` 标签，src 指向 `/api/attachment/thumbnail?key=...`）
2. 点击缩略图，验证弹窗显示原图（大图，src 指向 `/api/attachment/download?key=...`）
3. 点击弹窗背景关闭

### TC-08：消息展示——AttachmentInfoResponse 文件

**前置**：收到非图片文件消息
**步骤**：
1. 验证显示文件链接（文件名来自 `info.file_name`）
2. 点击链接，验证下载触发

### TC-09：消息展示——GroupChange / UserRemove 系统消息

**前置**：收到系统消息
**步骤**：
1. 验证系统消息居中显示，有别于普通消息气泡
2. 验证文字含义正确（"XX 加入了群组"/"XX 离开了群组"/"XX 已被删除"）

### TC-10：消息展示——Multi 类型

**前置**：收到 Multi 消息（同框多条内容）
**步骤**：
1. 验证多条内容在同一气泡框内显示
2. 验证各项之间有分隔线
3. 验证每项按各自类型渲染（文本/图片/文件链接）

### TC-11：历史消息分页

**前置**：当前会话有超过 20 条历史消息
**步骤**：
1. 首次进入会话，验证加载最近 20 条消息
2. 滚动到消息列表顶部，验证触发 `getMessagesBefore`
3. 验证追加的较早消息正确显示在列表上方

### TC-12：附件上传流程

**前置**：选择一个可发送会话
**步骤**：
1. 点击附件上传按钮，选择一个图片文件
2. 验证先发送一条 attachment 类型消息（`Content::AttachmentInfo`）
3. 验证获得 `transfer_id`
4. 验证上传文件数据到 `/api/attachment/upload`
5. 确认无误后提交查看文件，也可以边输入文本边看

ok 我确认一下，这个上传，是先上传拿到transfer_id再发消息吗？还是先发消息拿到transfer_id再上传？

答案是：先发消息拿transfer_id，再上传文件数据。

### TC-13：群组管理——创建群组

**前置**：在管理员下拉菜单中选择"群组管理"
**步骤**：
1. 输入群组名称
2. 选择成员（至少一个 user）
3. 点击创建
4. 验证群组出现在列表中
5. 验证该群组在会话列表中出现

### TC-14：群组管理——重命名群组

**前置**：存在可操作的多人群组
**步骤**：
1. 在群组管理中选择一个群组
2. 输入新名称
3. 点击重命名
4. 验证群组列表中名称更新
5. 验证会话列表中名称同步更新

### TC-15：群组管理——管理成员

**前置**：存在可操作的多人群组
**步骤**：
1. 在群组管理中选择一个群组
2. 添加一个成员、移除一个成员
3. 点击"添加成员"
4. 验证成员列表更新

### TC-16：群组管理——删除群组

**前置**：存在可操作的多人群组
**步骤**：
1. 在群组列表中找到目标群组
2. 点击删除
3. 确认删除
4. 验证群组从列表中消失
5. 验证会话列表中同步移除

### TC-17：群组管理——admin-user 单聊不可操作

**前置**：进入群组管理面板
**步骤**：
1. 验证 admin-user 单聊群组在列表中显示为禁用态
2. 验证不可进行重命名、管理成员、删除操作
3. 验证显示"仅可查看消息"说明

### TC-18：用户管理——新建用户

**前置**：在管理员下拉菜单中选择"用户管理"
**步骤**：
1. 输入用户名称（不输入 user_id）
2. 点击创建
3. 验证用户在列表中出现（有自动生成的 ID）
4. 验证会话列表中新增对应的 admin-user 单聊组
5. 验证群组管理列表中出现该单聊组（禁用态）

### TC-19：用户管理——重命名用户

**前置**：存在用户
**步骤**：
1. 在用户列表中点击目标用户的"重命名"按钮
2. 输入新名称
3. 提交
4. 验证用户名称更新
5. 验证会话列表中对应单聊组的名称同步更新

### TC-20：用户管理——删除用户

**前置**：存在用户
**步骤**：
1. 在用户列表中点击目标用户的"删除"按钮
2. 确认删除
3. 验证用户从列表中消失
4. 验证会话列表中的对应单聊组同步移除
5. 验证该用户从所有多人群组中被移除

### TC-21：管理员重命名

**前置**：成功连接
**步骤**：
1. 展开管理员下拉菜单
2. 点击"重命名管理员"
3. 输入新名称
4. 提交
5. 验证下拉菜单中的管理员名称更新
6. 验证下次连接后名称持久化

### TC-22：SSE 断线重连

**前置**：成功连接，SSE 已连接
**步骤**：
1. 停止后端服务
2. 验证前端显示断线状态或自动尝试重连（由 SSE 库处理）
3. 重启后端服务
4. 验证 SSE 自动重连成功
5. 验证新消息能正常推送

### TC-23：未读消息

**前置**：有多个会话，部分收到新消息
**步骤**：
1. 验证未读消息数在会话列表右侧显示
2. 验证超过 99 条时显示 `...`
3. 点击未读会话，验证未读计数清零
4. 切换回其他会话，验证之前清零未恢复

### TC-24：页面切换（消息/管理面板）

**前置**：成功连接
**步骤**：
1. 在消息区域点击"群组管理"（从下拉菜单）
2. 验证右侧切换为群组管理面板
3. 点击面板左上角 `←` 按钮
4. 验证右侧恢复消息区域
5. 同理验证用户管理面板的切换
