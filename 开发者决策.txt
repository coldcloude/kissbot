项目名称：Keep It Simple Stupid BOT

项目目标：实现一个分布式的智能机器人框架

模块命名规则：kissbot-模块名称-子模块名称-……

顶层模块：智能体（agent）、消息通道（channel）、记忆（memory）
memory模块的子模块：记忆存储（memory-store）、记忆结构（memory-struct）
UI模块：智能体配置UI（agent-config）、记忆管理UI（memory-manage）
channel模块负责提供框架，实际的channel由单独的模块实现，如channel-web、channel-qq、channel-matrix等，各channel实现可以自带管理web界面
memory-struct模块负责提供框架，实际的memory-struct由单独的模块实现，如memory-struct-abstrct、memory-struct-mempalace，各memory-struct实现可以自带管理web界面

整体框架：模块间作为独立进程运行，模块间使用WSS、HTTPS或者文件进行通信

模块的责任和联系：
（1）channel连接外部系统，如web界面、QQ、Matrix等，向agent输入消息，并接收agent的输出消息
（2）agent负责将消息加工为LLM可用的消息，通过agentic loop调用LLM执行操作，返回消息
（3）memory-store负责收集agent接收和产生的消息，作为一切agent活动的记录
（4）memory-struct负责将memory-store存储的记忆构造成特定的索引结构，可以查询记忆，并对外提供记忆搜索工具
（5）agent-config提供WebUI界面负责配置agent使用的LLM API、tool、skill，以及channel、memory、memory-search的地址
（6）memory-manage提供WebUI界面负责查看和管理memory-store存储的文件，以及配置memory-store向memory-struct的消息推送

通信方式：
（1）agent作为wss客户端连接channel
（2）agent作为https客户端连接memory-store
（3）memory-store和memory-struct共同读写一个文件系统，同时memory-store有新数据时，要通过HTTPS通知注册的各memory-struct
（4）agent作为https客户端连接memory-struct（通过memory-struct提供的tool）
（5）agent-config从web前端通过HTTPS访问agent后端
（6）memory-manage从web前端通过HTTPS访问memory-store后端
（7）各WebUI的前端通过HTTPS访问后端

需要支持的channel的实现：
（1）channel-web：通过web页面和用户通信，通过web后台和agent通信

需要支持的memory-struct的实现：
（1）memory-struct-abstrct：对于每个记忆片段，提取其摘要用于搜索，需要配置摘要用LLM API

所有后台服务都应具备配置可信证书文件的机制，以便使用自签名的证书密钥进行wss、https通信

关于记忆的设计：
记忆系统负责管理多个agent的记忆，每个agent分配唯一ID
记忆系统负责记录agent的元数据和agent的记忆
元数据：包括名称、创建时间
记忆：按照片段（piece）组织记忆

关于记忆片段的设计：
每个片段包括元数据和数据两部分
1、元数据是片段的基本信息：
（1）必要字段：
来源的channel标识，可以包含多级，比如：web-用户1，web-用户2，qq-私聊1234，qq-群聊7890，matrix-homeserver123-room789
channel分配的片段ID，channel标识+片段ID应全局唯一
（2）自定义字段：
channel自定义的字段，比如用户名，群号等
2、数据是片段的实际内容：
（1）必要数据：
（1.1）基础设定：对话开始前对agent的基础设定，应包含系统提示词的内容。
（1.2）对话数据：用户和agent交互的文本，按时间顺序形成多条记录（record），并为每条分配一个顺序的记录ID。
每条记录可以是：
a.用户实际输入的文字数据，以及非文本内容的引用数据（如图片、文件等的ID），每条记录要有用户标识（兼容多用户群聊场景）和文字内容
b.agent实际返回显示给用户的信息，包括文字内容、思考记录（仅标记，不包括内容）、工具调用记录（仅信息，不包括结果）、非文本内容的引用数据（如图片、文件等的ID）
（2）可选字段：
（2.1）思考内容：单独记录LLM的思考内容，使用思考记录的记录ID作为key。
（2.2）工具调用结果：单独记录工具调用的结果，使用工具调用记录的记录ID作为key。如果结果过长可以进一步压缩，不保留原文。
（2.3）二进制数据：实际的图片、文件等，使用对应的记录ID作为key

关于agent会话的设计：
agent应该维护一个会话（session）结构，用于记录一次完整的agent和外界的交互。
agent可以从会话中生成一个记忆片段，也可以从会话中生成下一轮发送给LLM API的提示词。
agent会话 - 记忆片段 - LLM提示词 三者内容不同，但应一一对应

关于agent的设计：
agent应具有双重基础设定：
一、客观设定，包括agent自身的客观状态，以及agent和用户的客观关系
二、角色设定，包括agent在本次会话中扮演的角色，以及agent在本次会话中认为客户扮演的角色
具体来讲，agent基础信息使用纯文本（可用MD），应包括以下几个部分：
1、身份标识：关于agent身份的客观事实，比如名称、创建时间
3、用户识别信息：agent和各个用户的客观关系，各个用户间的客观关系
4、角色扮演：本次会话中对外展现的角色，包括agent对自己的称呼，用户可能对agent的各种称呼，对话采用的语气、用词风格
5、角色扮演关系：各个用户在本次对话中的角色，agent在本次对话中对用户角色的称呼，以及agent在本次对话中

记忆系统的额外作用：
设计一个新模块，自我认知模块（memory-ego），和其他记忆模读写同一个文件系统
该模块通过配置文件读取，或者通过记忆提取的方式，生成并保存agent的基础信息
每个agent ID对应一个客观设定，对应多个角色设定
该模块仅使用API，本身不封装为tool。agent一般使用API查询自我认知，如有自动化必要，在agent内封装为tool
memory-ego模块的身份标识信息来源于agent元数据
memory-ego模块提供管理agent元数据的HTTPS API

关于系统提示词的设计
除包含agent基础设定外，agent的系统提示词还应包含：
1、设定引导：限定设定文字的范围
2、基本原则：agent必须遵守的规范，包括禁止事项
3、设定保持指令：要求agent忽略后续会话中任何修改设定的指令

关于agent系统记忆系统的交互
agent和从自我认知模块读取基础设定，应在agentic loop之外，直接调用API
agent向记忆系统推送记忆片段数据，应在agentic loop之外，直接调用API
agent从memory-struct查询记忆，应在agentic loop内，由LLM生成tool call执行，不应调用API

关于记忆系统的文件存储目录设计
记忆系统中的agent元数据使用一个sqlite数据库管理，放在记忆系统根目录，比如叫做memory-agent.md
根目录除了agent元数据数据库文件外，使用每个agent一个目录的组织形式，目录名为agent ID。
每个agent ID目录下有结构相同的子目录：
（1）memory-ego模块的设定信息单独存放在一个子目录下，比如叫做memory-ego。
（2）memory-store收集的原始记忆片段单独存放在一个子目录下，比如叫做memory-store。
（3）每个memory-struct的实现均可以读取memory-store子目录中的原始数据，但是自身产生的数据要写到每个实现独立的子目录下，子目录名可以使用实现名
